# API 契约

本应用是单用户本地工具（[ADR-0004](./ADR.md#adr-0004)）。HTTP API 有一个会话鉴权层：首次启动在登录页设置用户名和密码，之后所有页面与接口都要求登录；安全边界是「只有本机能访问 + 登录凭证」。本文只覆盖协议层约定（认证模型、错误形状、分页、SSE、备份端点），不逐条罗列业务字段；具体请求体形状以各 `route.ts` 的校验代码为准。

> 端点的存在性由 `src/lib/__tests__/docs-capability-contract.test.ts` 守住：新增 `route.ts` 而没登记进文末清单时，CI 会红。

## 1. 认证与来源校验

- **会话鉴权**：凭证存于数据库 `auth_users`（scrypt 哈希），会话存于 `auth_sessions`（只存令牌的 SHA-256 哈希）。会话令牌通过 `resume_life_session` httpOnly cookie 携带，有效期为 7 天，期间已登录请求自动滑动续期到满 7 天（带 1 小时节流窗口：窗口内的请求跳过续期写库与 cookie 刷新，读请求不再每次产生写事务）。
- **公开路径**：`/api/auth/*`（鉴权自身）与 `/api/health`（探活）不需要会话，在各自的 `withRouteErrorHandling` 调用上以 `{ public: true }` 显式声明；`/login` 页面公开。其余 `/api` 路由由统一包装器校验会话，未登录返回 `401 {"error":"未登录或登录已过期，请重新登录"}`。
- **proxy 的职责边界**：`src/proxy.ts` 刻意不引入数据库模块（middleware 构建产物会被源码级 NFT 分析静态解析出数据目录）。它只做 Host 白名单、uploads 封禁，以及对未携带会话 cookie 的页面访问重定向到 `/login`（cookie 在场检查，伪造/过期的 cookie 会被首个 API 401 拦下）；在 SSR 阶段直接读库的页面（首页）自行做真实会话校验。
- **首次初始化**：`POST /api/auth/init` 只接受回环 `Host`（`localhost`、`127.0.0.1` 或 `::1`，可带端口）；已初始化时还必须设置 `RESUME_LIFE_AUTH_REINIT=true`，成功逃生门请求会清除当前进程中的该变量并覆写凭证、清空全部会话，其他数据不动。远程 Host 即使开启该变量也返回 `403`。`GET /api/auth/status` 返回 `{initialized, allowReinit}` 供登录页选择表单。
- 所有 `/api` 请求与动态首页 `/` 先经 `src/proxy.ts` → `validateMutationOrigin()`：
  - 请求打到的 `Host` 必须属于白名单。默认只含 `127.0.0.1` / `localhost` / `::1`；反向代理对外使用其他域名时，把它写进 `RESUME_LIFE_ALLOWED_HOSTS`（逗号分隔）。条目可写成裸域名、`域名:端口` 或 `https://域名`，一律归一化成主机名后比较；无法解析的条目被丢弃并记一条 `origin.allowedHosts` 的 warn。
  - **只认 `Host` 头**，不认 `x-forwarded-host`（客户端可写）。因此代理必须保留原始 `Host`。
  - 读请求（GET）同样校验 Host：否则恶意页面可以靠 DNS rebinding 读走本机简历与 JD。
  - 变更请求（POST / PUT / PATCH / DELETE）若带了 `Origin`，还要求它与 `Host` 同源。
- 来源校验不通过统一返回 `403 {"error":"拒绝非本机来源的 API 请求"}`（先于会话校验）。
- 动态首页 `/` 与 `/api` 路由经过同一 Proxy 的 Host 校验与鉴权；头像由 `/api/uploads/[name]` 从私有数据目录提供，不支持公共上传路径。

## 2. 请求与响应约定

- **导入正文一致性**：`POST /api/import/parse` 的新生成 work/projects/custom 条目同时返回非空 `description` 与非空 `descriptionItems` 时，前者须等于分条按换行拼接后的全文（比较时仅统一 CRLF/CR 并忽略全文首尾空白）。不一致返回 502 和完整 `extractedText`，不返回部分 `modules`；保留单一正文来源与一致双正文的既有导入行为。页面可用保留原文重试或手工整理，历史记录的正文归一化规则不变。本地 OCR 对每个有可见内容的页面检查有效文字，任一页没有文字时返回含原页号的识别错误，不由其他页面的成功掩盖；视觉空白页仍允许为空。

- **简历 PDF 读取方式**：`POST /api/import/parse` 的文件上传表单可提交 `pdfMode: "auto" | "image"`，省略等同 `auto`。`image` 仅支持 PDF，显式将整份文件按页面图片送入当前 OCR 管线，适用于文字层顺序错误或漏字；最多 5 页，仍遵守 OCR 关闭／本地／视觉／自动降级设置、字符及渲染资源预算。不会将文字层与 OCR 全文重复合并。非法模式、非 PDF 的 image 模式、JSON 文本请求携带 pdfMode 均返回 400；只提取可同时提交 `extractOnly: "true"`，返回 `{ extractedText, ocr? }`，不调用结构化解析。页面切换方式后重新提取，失败保留既有原文；OCR 成功后结构化解析失败，重试复用已识别原文，不再次调用 OCR。读取方式只绑定当前文件选择，刷新需重新选择文件，已提取原文仍按既有暂存规则恢复。

- **简历文件来源**：DOCX 提取成功时（含确认没有原生表格的文件），`POST /api/import/parse` 返回完整 `extractedText` 和 `sourceReceipt:{version:1,id,expiresAt}`；`expiresAt` 为 Unix 毫秒。直接上传解析也先保存来源，模型失败后可用 `JSON {text,sourceReceipt:id}` 重试；JSON 响应不重复签发或延长来源编号，客户端保留请求时的回执。未知来源的纯文本及非 DOCX 沿用原消息。已知来源只发送一份按顺序拼接等于原文的 `tableDocument.segments`，客户端编号、哈希、会话与有效期不进入模型。表格来源不证明简历事实真实。

- **来源失效与清理**：回执绑定真实登录会话、当前数据世代和正文逐字哈希，有效期固定至签发后 30 分钟或会话到期中的较早者；普通进程重启或切换同数据目录下的进程仍可使用。格式错误或客户端提交 `tableProvenance/tableDocument/segments/provenance` 返回 400；未知、他人、已清理或过期回执统一返回 `410 / IMPORT_SOURCE_EXPIRED`，有效回执与提交正文不符返回 `409 / IMPORT_SOURCE_MISMATCH`；库内来源损坏脱敏 500。模型等待后再次检查来源、会话与世代，不返回失效来源的可用草稿。已提取原文在容量拒绝时仍返回，`429 / IMPORT_SOURCE_CAPACITY` 带 `Retry-After`；每会话 8 条/4 MiB、全局 64 条/16 MiB 的逻辑额度包含每条 512 字节开销，不驱逐其他有效回执，不承诺 SQLite 物理文件上限。`POST /api/import/source/discard` 接受 `{sourceReceipt:id}`，按当前会话幂等清理并统一返回 204，编号不得放 URL。请求体、提取和模型实际外发预算仍分别校验，不截断或删掉来源绕过 413。

- **来源恢复**：本标签页暂存将回执与对应原文一起保存，旧暂存按未知来源恢复，刷新不自动解析。原文逐字不变时保留来源；修改后清除，撤销到旧文也不自动找回。新原文和回执成功暂存后才尽力释放旧回执；存储失败保留内存稿和旧恢复记录，清理失败由固定有效期兜底，卸载不主动清理。收到来源失效、冲突或无法保留来源的提示后，仅由用户选择重新上传或按普通文本继续，不自动降级重发。可见恢复内容隐藏来源编号，CAS 仍比较未经改写的完整暂存；来源编号不进入简历模块或创建命令。

- **路径 ID**：动态 API 路径中的记录 ID 使用规范的正十进制写法，并且是正安全整数；例如 `1` 有效，`01`、`+1`、`1e0`、`0x1`、带空白值和超出安全整数的值无效。无效路径 ID 不会被转换为另一条记录的编号，路由按既有错误契约拒绝请求。查询参数和 JSON 请求体按各自字段契约解析。历史简历的详情 GET、复制来源、版本列表 GET 和版本快照 GET 也接受规范写法的零或负安全整数。目录支持复制历史草稿为新简历，版本树保留原编号用于只读查阅。新发布、编辑、删除和业务绑定仍要求正 ID。
- **简历目录删除**：确认展示 ID、完整标题、创建及更新时间、当前目录已发布版本数，以及草稿、模块、发布版、诊断、自我介绍和面试作答的级联删除范围；投递及提交快照、独立错题和复习历史、已生成追练与排雷记录保留，外键引用解除。从确认开始同步互斥删除与目录新建／复制；取消或 Escape 零写入并归还焦点。仅严格 `{ok:true}` 或同 ID 的 `404` 才移除并刷新；坏响应、网络、408／5xx 先只读核对原 ID 的完整简历详情，串 ID、坏结构或读取失败保持未知锁，仅提供重新读取；有效记录仍在后保留目录、允许重新明确确认，不自动重发 DELETE。服务端已收到的删除仍可能稍后完成。当前页过滤已确认删除 ID，列表刷新失败或旧响应不能复活；目录整份校验身份、标题、时间及版本元数据，不按创建长度限制截断历史标题。离页关闭当前／排队确认及本地请求等待，迟到结果不刷新新实例，不撤销已送达的事务，也不提供跨页持久删除回执。
- **简历目录写入归属**：新建与复制在同一事件同步互斥，并与删除互斥；提交采用实时标题，输入法组合期间 Enter 不创建。两类回复均需合法正安全整数 ID，复制 ID 不能等于原简历；成功新建保持锁直到导航离页，复制成功只读刷新目录，刷新失败保留旧目录与待创建标题。请求及失败提示绑定所属页面，离页后迟到回复不导航、刷新或显示旧提示。此目录流程没有新增创建／复制持久回执；异常后人工重新操作仍可能新增重复记录，应先核对目录，不能把页面同步锁视为持久幂等保证。
- **JSON 请求**：`Content-Type: application/json`，缺失或不是它则 `415`。请求体上限 1 MiB，超限 `413 {"error":"请求体超过 1 MiB"}`，非法 JSON 返回 `400 {"error":"请求体必须是有效 JSON"}`。
- **润色待填框架与正文语言**：新生成框架统一用 `[TBD: 待补内容]`，保留 `TBD` 标记，冒号后的内容按目标语言书写；兼容简短 `[待补充]`／`[待補充]`、独立的 `待补充`／`待補充`（可带一个句末标点）及已识别的法语、德语、日语待填标记。无来源的新生成结果只接受完整短标记或闭合括号框架，裸标记后不能附说明或经历句；带说明统一置于括号内，历史正文读取不受此生成校验影响。无原文框架的来源和关键词仍须为空，常规导出会阻断这些标记，勾选数字确认不能跳过。裸中文待填指令须从文字边界开始，不从“申請填寫”“跟進待確認訂單”等正常职责中截取词片段。语种识别仅用于 JSON 示例，不生成强制正文语言指令；完整目标中的转换方向、多语种、疑问、条件式或可选要求交由模型解释，示例语言不得覆盖实际正文要求，未指定时沿用原文。
- **简历润色输入**：`POST /api/resumes/[id]/polish` 请求体必须为对象。可选 `text`、`targetRole` 及 `context` 内的 `company/title/name/role` 必须是字符串，`sourceParagraphs`、`originalSourceParagraphs` 必须为全字符串数组，`context` 必须为对象；显式 `null` 或错误类型返回 `400`，不丢弃部分材料后生成。`moduleType` 只取 `work/projects/summary`，缺省为 `projects`；`mode` 只取 `star/quantify/summary/condense`，缺省按模块取 `summary` 或 `star`。工作/项目的 `summary` 仍归纳所属模块的经历，自我评价模块才提炼个人优势，均保留已有事实限定。二次精简用 `originalSourceParagraphs` 传入本轮原始事实，将 `text/sourceParagraphs` 中的待编辑草稿作为未确认结果对照；该字段仅允许 `condense`，其他模式返回 `400`。显式空数组表示没有原始事实，只允许待补框架、空来源和关键词，不把草稿当新证据；省略保持原有直接改写兼容，客户端精简 AI 草稿须携带原始资料。来源编号仍定位本次草稿条目，页面再映射回原始资料。原始资料及转义同样计入完整模型输入预算，超限 `413` 且零外发。空白原文仍允许生成待补充框架，润色响应不直接写入简历。
- **简历条件保存**：`GET /api/resumes/[id]` 返回标题／模块 revision 和 `resume.dataGeneration`（未恢复过数据时为 `null`）。标题、模块及整份草稿 revision 绑定当前恢复世代与对应实体；模块增删、改名、排序、模板及样式的 PATCH 必须原样携带读取到的 `dataGeneration`，编辑器正文保存也携带该世代。显式提交的世代必须匹配当前值；恢复后旧令牌、旧世代或已消失模块的写入返回 `409`，客户端保留草稿，需重新读取并人工合并。打印页模板切换使用页面加载时的世代，冲突后不自动换取新世代重试。
- **简历创建回执**：`POST /api/resumes` 可带小写 UUIDv4 的 `Idempotency-Key`。首次创建返回 `201 {id,title,request_id}`；同编号、同草稿重放返回 `200` 和原 ID，不新增简历；同编号改稿返回 `409`，原简历已删除返回 `410`。字段顺序和标题两端空白不影响匹配，正文、富文本、数组顺序和内部空白必须一致。无编号的旧调用仍按原规则创建。`GET /api/resumes/requests/[requestId]` 只读返回 `{request_id,status:"succeeded",id}` 或 `{request_id,status:"deleted"}`，未找到返回 `404`，不能据此认定在途请求不会稍后提交；无效编号返回 `400`。回执与简历和全部模块在一个事务中提交，只保存编号、输入哈希、结果引用和时间，不复制原文。删除简历保留编号墓碑，重启不丢失；业务备份排除此表，成功恢复清除回执并切换世代，失败恢复回滚。导入页先暂存编号再提交，坏响应或刷新后可用同编号回执找回结果，再核对完整草稿；回执损坏、正文已被修改或删除时保留草稿供人工核对，不自动重发 POST。用户可主动“重试本次导入”，仅沿用带回执标记的原编号和锁定原稿，提交前核对暂存未变；重试错误仍保留待核对状态，不解除原命令。当前页面已确认成功或删除回执后仅可继续读取或人工核对，不再提供写重试；显式另建仍需核对列表和确认重复风险。旧版暂存没有服务端回执标记时沿用原 ID/列表核对。
- **题库批量导入**：按去重后的非空题目计数，每次最多 500 道；超限整批返回 `400`，不写入前 500 道，原文应保留用于分批。
- **练习生成题量**：请求题量按整数限制为 1–20。模型有效题目去重后超过请求题量或为空时返回 `502` 且零写入；不足请求题量但非空时允许创建，`201` 的 `count` 返回实际持久化题量。
- **上传请求**：`multipart/form-data`，整体上限 12 MiB，单文件上限 10 MiB。超限返回 `413`，格式错误返回 `400`。
- **资源预算**：认证失败窗口、密码校验并发和 LLM 总并发由数据目录旁的 `process-budgets.db` 跨进程共享；视觉模型请求最多 5 张图片、单张 5 MiB、总计 20 MiB；仓库目录浏览最多返回 200 个子目录并带 `truncated`。
- **错误形状**：所有失败响应都是 `{"error": "<中文可读文案>"}`。未预期的 500 会额外带一个 `requestId`：

  ```json
  { "error": "服务器内部错误，请稍后重试", "requestId": "3f2a…" }
  ```

  把 `requestId` 贴进服务端日志（`server.log`）即可搜到这次请求的相关记录——包括 LLM 层的重试细节（`[server-info] {"operation":"llm.request",…}`）。
  已由路由处理的响应通过 `x-request-id` 响应头提供同一 ID；非流式模型调用自动继承请求关联 ID，路由返回的 502 会记录仅含关联 ID 和状态的脱敏诊断事件。
- **关联 ID**：请求可带符合 `[A-Za-z0-9._:-]{1,128}` 的 `x-request-id` 头，服务端会沿用它；无效或缺失时生成 ID。路由自身生成的错误响应与相关日志共用 ID；框架捕获的渲染异常日志也沿用有效请求头，但框架生成的响应不保证附带同一 ID。
- **导入暂存归属**：导入创建响应、回执更新、成功核对后的清理、明确拒绝后的解锁及人工允许另建，均先逐字比对命令最后成功写入或初始化实际读取的完整暂存原文，包含编号、原文、校对稿、结果 ID、回执标记和数据世代。记录后来被替换、修改、损坏或移除时，保留当前数据与待核对锁，不导航、不覆盖，提示刷新重新核对。损坏恢复只持有首次实际读取的原文；初始化无法读取时不能盲目清理后来出现的记录。“清除导入暂存”要求确认前后完整原文一致，主动清理不会顺带删除另一世代记录。这里的本地原文比较独立于服务端创建回执的草稿哈希规则；普通编辑也先核对本页最后成功读取或保存的完整原始记录，来源更换只有成功保存后才可释放旧回执。
- **列表删除确认归属**：题库、错题本、自我介绍、练习及五类工具历史共用的删除命令，将全局确认框、DELETE 与只读核对绑定到同一个取消信号。所属页面卸载时，只关闭本项正在展示的确认或将本项从队列移除，并结算确认等待；其他有效确认继续保留。确认阶段离页不发出 DELETE，重新进入后须重新确认；已经送达服务端的写入不会因本地取消而撤销。
- **面试历史删除**：单场与进阶系列分别固定端点和记录身份，共享从确认开始的同步互斥，并与面试创建互斥。确认展示 ID、完整 JD、参考简历、发布版和创建时间，说明对话／报告删除范围及收藏、追练保留。仅严格的 `{ok:true}` 或同一 ID 的 404 确认不存在；坏成功回复、网络、408、5xx 先以不缓存 GET 核对同一记录。核对校验身份、发布版绑定和历史正文／轮次结构，兼容未绑定发布版的旧记录、长原稿及接口将损坏报告标记 null 的情况；串记录、缺字段或读取失败保持未知锁，只能“重新读取删除状态”。有效读取仍存在则保留记录并允许重新确认，不自动重发 DELETE。已确认删除的 ID 在本页面按单场／系列分别过滤，防止旧列表复活或误删另一类同 ID；原列表仍含被过滤项时同步扣除累计场次，服务端刷新移除后不重复扣减。离页取消本项当前／排队确认及本地请求等待，迟到结果不能刷新新页面；不撤销已送达服务端的事务，也不提供跨页持久删除回执。
- **简历模块删除归属**：模块删除从确认开始同步互斥，使用当前编辑会话的模块列表定位目标，旧回调不能重开已删除模块的确认。确认框和本项失败提示绑定编辑会话取消信号，离页后关闭或移除本项，不影响其他有效弹窗；尚未加入保存队列的删除不再发起。已确认并加入共享队列的结构写入继续先排空正文草稿再执行，离页不取消该队列；迟到结果不能改变新会话，完成后仅在当前仍选中被删模块时选择后继，保留等待期间的新选择和其他模块的待保存输入。
- **简历版本分支归属**：从覆盖草稿的确认开始同步互斥，固定确认时的历史版本与草稿校验值；取消或失败后释放锁，成功后保持锁至导航离页。确认框及分支请求绑定所属版本页面，离页关闭或移除本项确认；确认后、共享自动保存排空后及响应返回后均核对页面归属。离页不取消共享自动保存，尚未发送的分支不再提交，迟到成功不跳回旧简历；已经送达服务端的分支仍可能提交，取消本地等待不撤销事务。页面内切换查看版本不改变已确认的目标，服务端原有草稿版本冲突校验继续生效。
- **简历版本发布归属**：提交时同步占有发布命令，防止同一事件重复提交或提交与关闭交错；先取消后触发的旧表单不能发布。排空共享自动保存、读取草稿校验值、发布回复三个阶段后均核对所属页面，读取与 POST 绑定页面取消信号；离页不取消共享草稿保存，尚未发送的发布停止，迟到成功不调用旧发布回调或跳回旧版本树。提交固定当时的名称与说明，失败保留输入，仅用户重新提交才重试；回调成功后可继续发布下一版，导航成功前继续保持互斥。服务端已接收的发布仍可能完成，本地取消不回滚事务；此保护不提供跨页持久请求回执或未知结果去重。
- **草稿清理确认归属**：设置页“清除本机敏感副本”、导入页“清除导入暂存”及“已核对，允许再次创建”的当前／排队确认均绑定所属页面的取消信号，离页移除本项确认，旧入口及确认后同事件离页不能清理或解锁新实例。重复点击仅一次确认；取消／Escape 保留原稿和待核对状态，并归还触发按钮焦点。解析与清除导入暂存从同事件同步互斥。设置页清理处理脱敏规则、各数据世代的项目源码路径、自定义 CLI 客户端配置及本标签页简历编辑器草稿和保存队列；导入暂存与谈薪恢复记录不在该清理范围。导入清稿仍要求完整暂存原文未变且无待核对创建；人工允许再次创建只清待核对标记并保留校对稿，不自动发送 POST，也不撤销服务端已收到的创建。
- **缓存**：API 响应默认不可缓存；头像接口 `GET /api/uploads/[name]` 返回 `Cache-Control: private, no-store`。恢复备份可能用新内容覆盖同名头像，恢复事务会更新头像 URL 的持久 `?v=<UUID>`，避免复用被同名内容替换前的资源标识。头像文件仍按不含查询参数的文件名读取。
- **恢复冲突**：普通 API 请求绑定开始时的数据世代；备份恢复后，旧请求不能提交模型、解析或其他异步结果。尚未开始响应的请求返回 `409 {"error":"数据已恢复，请刷新后重新操作"}`；已经开始的 SSE 发送 `error` 事件并停止，不发送成功的 `done`。客户端应整页刷新后重新发起操作。
- **生成命令锁**：同一应用进程内，命令锁按数据目录、恢复世代与命令编号隔离。同一世代的重复命令仍在模型调用前返回冲突；刷新到恢复后的新世代后，旧世代的命令锁不再阻塞新命令，旧任务的完成或释放不能解除新锁，也不能提交旧结果。此锁不替代跨进程的事务与条件写入校验。
- **客户端数据世代**：页面在请求时输出 `resume-life-data-generation` meta，`apiFetch` 为该文档固定世代，并将其放入 `X-Resume-Life-Data-Generation` 请求头；JSON、SSE、上传和下载均沿用该包装。未恢复过数据时头值为 `initial`，与简历 JSON 中的 `null` 表示同一世代。普通 API 响应也带同名响应头，但旧文档不能从后台响应自动采用新世代。浏览器的受保护变更请求（带 `Sec-Fetch-Site` 的 POST/PUT/PATCH/DELETE）缺少该头或携带旧值时返回 `409`；已携带旧值的读请求也返回 `409`，避免混用恢复前后的内容。服务端入口和现有事务内复核共同保护恢复竞争。认证、健康探针与主动恢复端点不受该客户端校验约束。无 Fetch Metadata 的脚本可保留原有无头调用方式，或原样携带此前读取的世代头获得冲突保护。

简历 Markdown、PDF、DOCX 的导出 POST 都使用上述有界 JSON 解析，且请求体必须为对象；`{}` 表示普通导出。传入 `anonymizeConfig` 时必须提供完整有效的 `AnonymizeConfig`（各项 `enabled` 为布尔值、`mode` 使用对应合法枚举、`customRules` 为有效替换规则数组）；无效配置返回 `400`，不会回退为未脱敏附件。非法 JSON、错误 Content-Type 和超限请求分别返回 `400`、`415`、`413`，且不生成附件。

三种格式的 GET/POST 在渲染前均检查模块完整性；损坏模块返回 `422 {"error":"导出已暂停：部分模块数据损坏，请修复后重新导出。","corruptedKeys":["work"]}`，不生成附件。`skipExportCheck: true` 仅跳过数字/占位符核对，不能绕过完整性检查。自定义脱敏规则在内建遮盖之后应用于全部可见的基本文本字段（姓名、性别、年龄、电话、邮箱、地点、生日、链接），不改头像路径和排版元数据。

简历 DOCX 导出使用 `GET/POST /api/resumes/[id]/export/docx`，返回 `application/vnd.openxmlformats-officedocument.wordprocessingml.document` 附件。POST 接受 `{ confirmedIssueIds?: string[], anonymizeConfig?: AnonymizeConfig }`；未确认数字或残留占位符返回 `409`，脱敏前后均检查。文档保留模块顺序、正文、标题、列表、加粗、常用文字颜色与换行，并按当前模板生成顶栏、头像、章节装饰和双栏。职位与日期位于同一行；脱敏附件名使用脱敏后的标题，头像按脱敏设置处理。Word/WPS 的分页、边缘横幅和圆角效果可能与浏览器生成的 PDF 有细微差异。

双栏 DOCX 与网页共用模块分流规则，按 `asideModules` 的模块类型或具体 key 分配；省略或空数组沿用经历主栏、其他内容侧栏的默认规则，非空但无匹配时侧栏为空。导出保留 `asidePosition`、侧栏宽度/背景/边框、内边距和栏间距；技能标签底色按所在栏背景合成。

自我介绍详情 `GET /api/intros/[id]` 的每个版本包含 `revision`。手动保存 `PATCH /api/intros/[id]/versions/[kind]` 必须提交 `{ sentences, baseRevision }`；缺失或格式无效返回 `400`，版本已改变或恢复导致修订失效返回 `409`，不会覆盖已保存内容。手动句子数组必须包含 1–60 句，每句正文为非空字符串且不超过 800 个 UTF-16 码元，点评若提供须为不超过 300 个码元的字符串；非法或超限整组返回 `400`，不会过滤句子、截断正文或写入部分内容。重新生成和重新点评 POST 接受 `{ kind, baseRevision? }`；省略时使用请求开始处理时的服务端快照，提交时仍检查快照。三种成功写入均返回 `{ kind, sentences, revision }`，下一次操作使用新令牌。页面遇到冲突会保留编辑草稿，获取最新版本后由用户核对并再次保存。

详情页“重新构思本版”的确认属于当前记录：离页或切换记录会关闭本项正在展示的全局确认，或移除本项排队等待，其他有效确认继续保留；确认阶段取消不发出重生成 POST。重新进入需要重新确认，已提交请求仍沿用原有修订冲突与结果核对流程。

历史版本读取只校验句子结构，不套新生成的篇幅上限；正常正文与点评不截断，省略的点评兼容为空字符串。原稿 JSON 损坏、不是非空列表、存在无效/空白正文或非文本点评时，详情保留该版本并返回 `sentences: []`、`read_error` 和完整存储字符串 `raw_sentences`，不筛掉异常项。其 `revision` 仍绑定原始存储内容；即使提交当前修订，普通保存也返回 `422`，不会用部分句子覆盖原稿。可显式确认重新生成本版：模型失败保留原稿，成功只替换选中版本。准备页及资料候选列表共用同一历史结构校验；异常短版显示原稿异常提示，正常摘要最多展示 400 个码元，不改写原稿。

演练页在写入响应丢失、损坏、408、5xx 或返回版本不完整时，先通过不缓存的详情 GET 核对原版本修订：改变则展示最新存档并提示核对，未变则保留原错误与草稿、提示上次请求仍可能稍后完成，用户核对后决定是否显式重试。其他明确 4xx 沿用校验或冲突流程。读取也失败或状态不完整时，只提供重新读取入口并禁用三种写入，切换版本不解除锁定；恢复读取不触发模型。最新修订可能来自其他页面，不能单靠修订变化证明本次写入成功。待确认状态仅存在于当前挂载页面，服务端仍在处理时也可能读到旧修订；本流程不提供持久请求幂等保证。

详情初次加载、冲突获取最新版本与异常写入核对均使用不缓存的 GET，并与删除核对共用完整存档校验：记录 ID 必须匹配，简历 ID 为正安全整数，标题、JD 和创建时间为字符串，发布版绑定三字段必须同时为 null 或构成完整有效绑定，各版本种类唯一且修订与历史句子结构有效。损坏元数据不会被采用，不能据此解除写入待确认锁，已有草稿继续保留。缺版、长历史及显式标记的异常原稿仍可读取。详情日期与列表共用展示规则：纯 YYYY-MM-DD 原样显示（含旧无效日历字面量），不可解析时间保留原文，空串显示“未记录时间”，真实时间戳按浏览器当地日期展示。

创建 `POST /api/intros` 的 `resume_id` 必须为 JSON 数字类型的正安全整数；布尔值、数组、字符串、null、缺失及非正/不安全整数返回 `400`，不会隐式转换成其他简历 ID、调用模型或创建记录。详情 GET/DELETE、手动保存、重生成及重新点评的路径 ID 也统一要求转换后为正安全整数，非法时返回 `400`；合法 ID 对应记录不存在仍返回 `404`。创建保持 SSE 协议，但不再转发未校验的模型 `delta` JSON；两版完整校验并事务保存后才发送 `done { id }`，失败发送 `error`，保活继续生效。合并生成达到模型输出上限时会丢弃截断结果，再按 30 秒版与 2 分钟版分别生成；只有两版均完整有效才一起保存。确认未写入的生成失败以 SSE `error` 的 `outcome: "not_saved"` 标记，可直接重试；其他失败不带该标记，提交状态仍需核对。页面核对完成 ID 为正安全整数后导航；完成事件损坏时保留输入、重读历史供用户核对，不自动发起第二次创建，也不按简历与 JD 猜测唯一结果。

创建在同一提交事务内重新确认本次所选发布版仍存在、属于原简历，且实际传给模型的职业材料未变，再创建介绍、两版句子及投递资料关联。材料变化或删除时发送明确的 SSE `error`，不保存晚到结果；投递 JD、绑定或存在性变化时保留相应业务错误。模型等待期间不持有写事务；修改当前草稿、标题排版、其他版本或后来发布新版本，不影响已固定的本次材料。省略发布版时只在请求开始时选择最新版本，提交时不重新选择。数据恢复继续由既有全局世代保护拒绝旧任务；关联写入失败时仍整组回滚。流已开始后的这些错误保持 HTTP `200` 的 SSE 错误事件，不自动再次调用模型或创建记录。

工坊保留生成失败的原始原因与 JD 草稿。HTTP `4xx`（排除 `408`）及包含非空字符串 `error` 的完整 SSE 错误事件显示“请按上方提示处理后再生成”；`408`、`5xx`、网络中断、损坏错误事件或不完整完成响应继续提示结果仍可能已保存、先核对历史。失败后均重读历史，不自动重发创建；新请求开始清除旧错误分类。共享 SSE 客户端以 `HttpError` 保留 HTTP 状态，以 `SseServerError` 区分完整服务端错误事件；该类型只表明收到失败事件，不单独证明任意业务完全没有写入。`outcome: "not_saved"` 仅用于明确在任何写入前终止的自我介绍生成失败。

结果未知的提示始终提供“重新读取历史”，即使上一次读取已成功且没有新记录也可再次主动读取，避免为找回晚到存档而刷新整页、丢失 JD。该操作复用历史首页的不缓存读取、整页校验与分页重置，加载期间禁用入口；读取失败或损坏响应时仍可重试，保留当前 JD、简历及发布版选择。重新读取不提交创建、不调用模型、不自动跳转或凭相同 JD 认领记录；当前历史没有新记录也不能证明在途请求不会稍后保存，用户需核对真实存档后决定后续操作。此入口不新增持久请求回执或幂等保证。

面试主作答与重新作答评分均要求四维完整、有限的 0–10 整数评分和非空点评。重评还要求非空参考答案，模型返回非法结构时返回 `502`，不追加重答历史或修改既有参考答案；历史记录中的空评分仍可读取。模型可重试 HTTP 错误的 `Retry-After` 秒数或 HTTP 日期会作为最小等待时间，与既有退避取较大值；等待期间仍受调用总截止时间和客户端取消约束。

### 保存版本与损坏数据

排版保存额外要求携带读取到的 `resume.styleRevision`（请求字段 `styleRevision`）；缺失或失配返回 `409`，不写入任何字段。此令牌只绑定排版、简历与恢复世代，正文保存不会自动推进客户端的排版基线。排版冲突保留本页微调值，需重新加载最新设置并人工合并。

草稿 `style_overrides` 无法解析为对象时，读取保留原始记录、返回 `resume.styleCorrupted: true` 和明确警告，默认样式仅用于修复预览。版本发布、Markdown/PDF/DOCX、作品集及打印均拒绝损坏排版，跳过数字核对不能绕过此限制。用户在编辑页显式选择“使用模板默认排版修复”或保存排版调整后解除限制；修复仍要求原始 `styleRevision` 和数据世代，不能覆盖其他页面的新排版。

`GET /api/templates` 对损坏样式返回 `corrupted: true`；其 `style` 仅为修复预览的默认样式，原始记录保持不变。选择器禁用损坏模板；样式工厂经用户确认载入修复草稿，显式保存后才解除损坏状态。应用、发布或导出损坏模板返回 `422` 与修复提示。打印页加载自定义模板失败时也禁止直接打印，不能默默换用默认模板。

样式工厂的保存、AI 生成、修复确认和删除共用同步互斥边界；正常模板选择、名称与样式编辑仍可进行，迟到保存不覆盖新编辑。确认、请求及失败提示绑定所属页面的取消信号，离页移除当前／排队确认并中止本地等待。修复确认包含模板 ID 与完整名称，确认只载入草稿；删除确认还包含创建／修改时间，说明模板及模型标签删除、引用简历回退经典单栏，而正文和简历级样式覆盖保留。取消／Escape 零写入并归还焦点。

模板 DELETE 只接受严格 `{ok:true}` 或目标端点的 404 确认不存在。网络、408、5xx 或残缺成功响应先以 `cache:no-store` 读取完整 `/api/templates` 列表；该域没有单项 GET，不将列表端点的 404 当成目标不存在。列表必须为合法、无重复正安全整数 ID 的完整模板行；无法读取或结构异常时保留列表与草稿，锁住写入，只允许“重新读取删除状态”。确认目标仍在则提示核对并释放锁，不自动再删；确认不在则解除目标编辑绑定、保留检查器草稿，在本次挂载会话过滤该 ID，刷新失败或旧列表不能复活它。保存回包同样核对模板字段及 PATCH 目标 ID，列表刷新失败独立展示。上述锁与过滤只属于当前页面，不提供跨页回执或幂等；离页不回滚服务端已收到的操作，一次列表读取也不能证明在途删除不会稍后完成。

浏览器打印与服务端导出同样拒绝非空 `corruptedKeys`；“无需核对”只跳过数字/占位符检查，不能跳过数据损坏。面试总结必须包含有效匹配分及非空的强项、短板、建议；挖掘模式还要求完整经历字段、草稿与待确认项结构。生成结果不完整时返回 `502`、保留原状态并允许重试。面试官评估允许独立重试。

## 3. 分页

游标分页，稳定排序，不使用 offset：

- 查询参数 `limit`（默认 50，上限 100）、`cursor`（上一页返回的 `nextCursor`）。
- 响应形状：

  ```json
  { "items": [ … ], "nextCursor": "123" }
  ```

  `nextCursor` 为 `null` 表示没有下一页。客户端在「加载更多」时把上一次的 `nextCursor` 原样回传。`/api/interviews` 与 `/api/interviews/series` 还返回独立统计的 `total`（不受关键词和分页游标影响），用于展示累计场次。
- 参数非法（非数字、越界）返回 `400`。

采用游标分页的列表：`/api/applications`、`/api/drills`、`/api/bank`、`/api/notebook`、`/api/interviews`、`/api/interviews/series`、`/api/interviews/question-graphs`、`/api/projects/[id]/summary-history`。

历史记录接口 `/api/intros`、`/api/tools/jd-portraits`、`/api/tools/jargon-decodings`、`/api/tools/career-gap-remedies`、`/api/tools/salary-negotiations` 也按 `id` 降序分页，统一返回 `{ "items": […], "nextCursor": "…" | null, "total": 记录总数 }`，`total` 不受游标影响。未传分页参数时返回默认的前 50 条；读取全部历史记录需要逐页请求。

自我介绍历史在展示或追加前整页核对正安全整数 ID、JD、简历标题、创建时间和发布版关联：已绑定记录保留版本 ID/编号/名称，旧未绑定记录的三个版本字段均为 null。严格验证 ID 倒序、请求边界及满页末项游标，损坏项、重复边界和短页假游标整页拒绝；续页失败保留已加载记录和原游标，单独重试历史不清空 JD 或改变参考简历/发布版，不触发重新生成。历史长文本及合法空字段原样读取，不套用新生成的篇幅限制；无法解析的日期显示原字面量，空日期显示“未记录时间”。形如 YYYY-MM-DD 的旧日期原样显示，不按 UTC 时间戳换算或自动校正；实际时间戳按浏览器当地日期展示。列表顺序以记录编号为准。

自我介绍删除从确认开始同步串行，与生成互斥；确认显示完整 JD、参考简历、发布版及创建时间，取消不写入。`GET /api/intros/:id` 与 `DELETE /api/intros/:id` 仅接受正安全整数 ID，否则返回 `400`。删除只认 `{ "ok": true }` 或同 ID 的 `404`；网络错误、`408`、`5xx` 和损坏完成响应只读核对同 ID，不自动再次删除。核对 `404` 才确认不存在；核对完整存档仍存在则保留记录、允许重新确认；坏结构、串 ID 或读取失败时保持结果未知，仅提供“重新读取删除状态”。核对兼容长历史、未绑定发布版、缺版及明确 `read_error` / `raw_sentences` 的旧原稿。页面离开后取消本地等待，迟到结果不得刷新新实例；这不表示撤销已到达服务端的删除。当前挂载期间过滤已确认删除的 ID，刷新失败或旧列表不能复活卡片；存在本地删除标记时不展示可能过期的服务端总数，当前页全被移除仍保留真实后续游标。服务端沿用事务删除两版内容及擦除关联日志标题，失败时一同回滚，匿名用量与其他记录保持不变。

**刻意不分页的例外**：`/api/resumes`、`/api/projects` 返回完整列表——它们要作为面试/项目选择器的数据源，分页会破坏选择语义。

## 4. SSE 事件协议

长耗时 AI 流程（模拟面试出题、作答评分、自我介绍生成、项目总结）走 Server-Sent Events。响应头为 `Content-Type: text/event-stream`，每 15 秒发一次 `: keep-alive` 注释心跳。

事件类型：

| event | data | 含义 |
|---|---|---|
| `delta` | `{"text": "…", …extra}` | 增量文本，客户端拼接展示 |
| `done` | 业务载荷（如 `{"id": 12, "question": "…"}`） | 成功终态，流随即关闭 |
| `error` | `{"error": "…", "outcome": "not_saved"}`（仅在确认写入前失败时含 `outcome`） | 失败终态，流随即关闭；没有标记时不能据此断定写入结果 |

`error` 事件里的 ID 就是日志中的 `requestId`：用户界面上的报错可以直接拿去搜日志。

共享 SSE 客户端兼容非流式 JSON 完成响应，但必须先成功解析 JSON；HTTP 2xx 的 HTML、空正文或损坏 JSON 不触发完成回调，而是报告响应无效，不能据此确认业务已保存。正常 JSON 载荷仍由业务回调校验，非 2xx 保留 HTTP 状态与服务端错误文案，主动取消继续静默处理。

## 5. 备份端点

导出的**密码在 JSON 请求体**；校验与恢复的**密码在请求头**，请求体是加密备份流本身。

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/backup/stats` | GET | 数据统计（各表行数、数据库文件大小），供设置页展示 |
| `/api/backup/export` | POST | 导出 `.rlbackup` 加密备份 |
| `/api/backup/validate` | POST | 只校验并预览备份内容，不写入 |
| `/api/backup/restore` | POST | 用备份覆盖当前全部数据 |

### 自定义请求头

- **`X-Resume-Life-Backup-Password`** — `validate` 与 `restore` 的备份密码。密码**不放请求体**，因为这两个端点的请求体是加密备份流本身。
- **`X-Resume-Life-Preserve-Ai-Config`** — `restore` 专用，取值只能是 `"true"` 或 `"false"`，其他值返回 `400`。**缺省为 `true`**，即完整保留本机当前的 AI 配置。传 `"false"` 会用备份中的 Base URL、模型名等普通设置替换本机设置；用户备份不携带 API Key 或代理密码，需要重新填写。

  缺省取 `true` 可防止不带该头的脚本或客户端覆盖正在使用的本机配置，导致恢复后需要重新配置模型连接。

### 导出请求体

```json
{ "password": "至少12个字符", "confirmation": "同上" }
```

密码为 12–256 个 Unicode code point；两次不一致返回 `400`。导出响应是流式附件，`Content-Disposition` 带时间戳文件名。

用户导出的 `settings` 行会将 `api_key` 与 `proxy_password` 清空，包括设备绑定的加密值；服务地址、模型名、协议与 OCR 模式等普通设置保持原值。

### 容器内容

加密容器（`.rlbackup`，manifest 格式版本 `1.0.0`）的明文按记录顺序为：

| 记录 | 说明 |
|---|---|
| `{ kind: "manifest" }` | 应用名、格式版本、数据库版本、导出时间、完整表清单、自增序列，以及 `files` 头像清单（`name` / `bytes` / `chunks`） |
| `{ kind: "row", table, data }` | 逐表按 rowid 游标分页导出的业务行 |
| `{ kind: "file", name, index, data }` | 数据库引用的 `data/uploads/` 头像文件，按 1 MiB 原始字节分块、base64 编码 |
| `{ kind: "end", stats, totalRecords, files }` | 各表行数、总记录数、头像文件数 |

`manifest.files` 与 `end.files` 都是必需字段：没有头像时分别填写 `[]` 与 `0`。恢复只接受当前完整的首版容器格式，不支持缺少这些字段的旧格式。恢复时会先写头像文件再在事务里换数据，保证不会出现「库里有指针但文件不存在」；备份里缺失分块或长度与清单不符的头像会让整次恢复失败。新数据库不再引用的本机头像会先隔离，提交成功后清理，失败时放回原位。

### 恢复的原子性

恢复失败时原数据不被替换，响应为 `500` 且带 `requestId`：

```json
{ "ok": false, "error": "恢复失败，原数据未被替换，请根据关联 ID 排查", "requestId": "…" }
```

每次成功恢复前会先创建一份 SQLite 灾备快照（`VACUUM INTO`）和同名 `.uploads` 头像目录，最多保留 5 份；`snapshotCreated` 返回 SQLite 文件路径，手动回退还需一并还原其头像目录，参见排障指南。

设置页恢复确认固定已经验证的文件对象、密码及 AI 配置选择，展示文件名／字节数、导出时间、数据库版本和总记录数，并说明投递快照及复习历史等全部业务数据的覆盖范围。确认开始即与导出同步互斥，不能替换文件、修改密码或配置，连续点击只产生一次确认和一次恢复请求；取消／Escape 零恢复并归还触发按钮焦点。离页取消当前／排队确认及所属请求的本地等待，迟到结果不清理新实例；取消本地等待不撤销服务端可能已提交的恢复。

校验面板只接受严格 `ok:true`、正确应用／格式身份、有效导出时间、唯一表名及非负安全整数逐表计数，逐表计数须与总记录数一致。校验与恢复响应的 `stats` 均只包含原包 `manifest.tables` 中的表；旧包暂存时为当前数据库新增表补入的零计数仅供内部恢复使用，不混入响应。恢复完成只接受严格 `ok:true`、与本次已验证备份一致的逐表计数和非空 `snapshotCreated`，随后清理本页文件／导入密码并等待用户保存灾备位置、手动刷新。此完成响应不是持久请求回执，也不能用相同计数证明两份备份内容相同。

明确 4xx 拒绝（408／499 除外）保留文件、密码和校验结果，允许用户重新明确确认；网络、408／499、5xx、不可读／残缺或不符的完成回包显示“恢复结果尚未确认”，保留输入并锁定再次恢复及导出，不自动重发或将统计相同当作成功。用户先核对业务数据与恢复前灾备，再“核对后允许再次恢复”，明确确认再次覆盖会清除恢复后新增或修改的数据；该确认仅解除本页锁，随后仍须重新确认恢复才发 POST。取消继续锁定，解锁确认同样随离页取消。没有新增恢复幂等或跨页回执，重开／刷新页面不保留此锁；实际恢复后旧文档的普通读写仍受既有数据世代保护，需整页刷新后继续使用。

## 投递快照

`POST /api/applications` 与 `PATCH /api/applications/[id]` 的 `resume_id`、`resume_version_id`、`interview_id`、`interview_series_id` 仅接受 JSON 数字类型的正安全整数。布尔值、数组、对象、数字字符串、非整数、非正数和超出安全整数范围的值返回 `400`，不新增或改变投递、快照与准备资料关联；领域直接调用遵循同一规则。未提供字段保留原部分更新语义。`resume_id`、`interview_id` 和 `interview_series_id` 提供 `null` 或空字符串可清除关联；发布版 ID 始终与简历绑定，已有简历存在时省略或清空 `resume_version_id` 仍按既有规则解析默认发布版。

投递 POST/PATCH 的请求体必须为 JSON 对象；提供的 `company`、`role`、`salary_range`、`jd`、`next_interview_at`、`notes` 必须为字符串，错误类型（含显式 null）返回 400，不丢弃字段后创建或部分更新记录、阶段及投递快照。领域写入也执行相同校验。省略可选字段仍沿用创建默认值或 PATCH 保持原值；空字符串仍可清空可选文字，公司与岗位仍要求非空。首尾空白按既有规则清理，内部空格、换行、标签和实体字面量保持原样。文字字段的 null 拒绝与上述关联 ID 的 null 清空语义分别处理。

新建 `stage=applied` 的投递，或首次从其他阶段切换为 `applied` 时，服务端在同一事务中保存当时已落库的关联简历与本次 JD。每条投递只有一份固定快照；普通编辑、重复标记、阶段回退后再次投递和更换关联均不覆盖快照。未关联简历时仅保存 JD 和时间。历史已投递记录不会因普通编辑自动补造快照。内容损坏或合并后的记录超过备份容量时，整次保存回滚并返回 400。

`GET /api/applications/[id]/versions` 按需返回 `submitted`（`captured_at`、`resume`、`jd`）和 `current`（`resume`、`jd`、`warnings`）。没有快照时 `submitted=null`；没有对应简历时 `resume=null`。列表仅提供 `submitted_at`，不附带快照正文。快照字段不在 POST/PATCH 输入白名单中。

看板和面试日历均可回看投递版。差异按模块 key 对齐，比较正文、内联加粗/列表标记、模块顺序及 JD；头像、页面模板和间距不参与差异统计。

投递删除由看板页面统一管理确认与请求。确认包含投递 ID、完整公司／岗位、阶段、批次及创建／更新时间，并说明投递快照、阶段履历、真实面试轮次及逐题记录／复盘／导出关联、准备待办及资料引用的级联范围；简历及发布版、独立准备素材、收藏与复习历史、已生成追练保留。确认及等待绑定页面取消信号，离页关闭当前／排队确认，迟到回复不刷新新页面。从确认开始同步互斥其他删除、新建／编辑入口、轮次登记、阶段推进与日历快捷更新；取消或 Escape 不写入且归还焦点。

卡片操作在键盘焦点进入时保持可见，取消确认后不将焦点归还到透明按钮。删除错误或确认结果出现时聚焦反馈区域，使手机长页面中的未知提示和重新读取入口进入视口；不会因取消确认而抢走原触发按钮焦点。

投递新建／编辑弹窗按投递 ID 及起始阶段／排期隔离表单实例，保存从同一事件开始同步防重；等待中字段与关闭按钮禁用，背景和 Escape 也不能关闭。请求携带本实例取消信号，离页或切换目标后迟到回复不调用旧成功回调，不回滚服务端已提交的写入。成功回复必须为完整投递，编辑须匹配原 ID，并核对本次提交的文字、阶段、招聘环节、关联 ID 与排期；终止后的招聘环节按服务端规则取终止阶段。严格成功保持互斥至宿主关闭弹窗。

保存遇到坏成功回复、网络、`408` 或 `5xx` 时保留原稿并暂停再次提交，不显示保存成功。编辑可点“重新读取保存状态”只读 GET 原 ID，完整且与提交一致才完成；坏记录、字段已改变、404 或读取失败保留草稿和未知保护，不自动再写。新建没有可确认的记录 ID，不按同名条目推断创建归属，也不自动再次 POST；提供另开窗口的“核对投递记录”入口，当前原稿继续保留。未知时可以关闭弹窗，但关闭后重新创建仍可能新增重复投递，需先人工核对。明确的其他 4xx 拒绝允许修正后主动重试。此保护只属于当前表单实例，没有新增持久回执／幂等协议；编辑回读一致只证明当前内容与提交相同，不能证明某次在途事务不会随后完成，也不提供跨标签编辑冲突控制。

仅严格 `{ok:true}` 或目标 DELETE 的 `404` 直接确认删除；坏回复、网络、`408` 或 `5xx` 以不缓存 GET 核对同一投递的完整详情、合法阶段及关联 ID、轮次／阶段履历归属和待办。串 ID、残缺详情或读取失败保持未知锁，只允许重新读取删除状态，不自动再次 DELETE；合法详情仍在则提示核对后重新明确确认，详情 `404` 才确认消失。当前页面过滤已确认删除 ID，刷新失败或旧列表不能复活卡片，搜索保留。编辑前的详情读取也核对同一完整投递，读取等待与提示绑定页面。服务端删除事务与级联未改变，离页不回滚服务端已收到的操作，也不提供跨页持久回执；一次回读不能保证在途删除不会稍后完成。其他写入的持久幂等及未知结果恢复协议不在此删除流程内。

## 岗位诊断历史

`POST /api/resumes/[id]/diagnose` 每次追加独立记录，保存岗位标识、岗位名称、JD、报告和模型调用前读取的简历正文快照。请求支持 `jd`、可选 `job_title`、已有岗位的 `job_id`，以及创建独立岗位的 `new_job=true`；已有岗位可修改 JD 后继续诊断。未指定岗位标识时默认复用相同 JD 的岗位。编辑器发起诊断前等待简历保存成功，基本身份联系方式仍不发送给模型。

诊断需要原样保存完整快照，调用模型前使用与历史读取、备份相同的存储结构校验。旧快照缺少归档字段、基本信息容器损坏或标题／模块排序类型错误时返回 `422`，提示核对修复后重新发布或恢复有效备份；不消耗模型调用、不写入不可读报告、不清洗原版本。仅排版异常不影响诊断快照归档。此要求独立于其他生成入口只读取职业材料的校验。

所选发布版本没有职业模块（仅含基本信息或零模块）时，在调用模型前返回 `422`，提示补充经历、技能等职业模块并重新发布后再诊断；不产生新报告。仍有职业模块但其内容为空时，可正常评估其信息缺失。自我评价 `text` 与技能 `items` 的模型改写建议使用显式空字符串 `item_id`；经历 `description` 则使用原条目 ID，不能混用模块 key。

简历模块保存拒绝同一经历列表内重复的非空显式 ID，也拒绝同一经历内重复副项 ID；缺省或空 ID 仍按既有规则生成，不自动给旧记录重新编号。诊断改写建议必须定位唯一模块和唯一经历；旧重复快照中的歧义建议整份拒绝，当前草稿目标重复时不应用建议或记录采纳，避免一次改写覆盖多个公司的正文。

`GET` 返回 `current`、同岗位的 `previous` 和不带快照正文的 `history`，也保留顶层 `jd`、`report`、`created_at` 字段。默认选中最新记录；可用 `job_id` 查询该岗位最新记录，或用规范正十进制安全整数 `diagnosis_id` 读取指定历史版本。首次诊断的 `previous=null`。备份恢复要求数据库版本与当前支持的结构版本匹配，认证凭证和会话不随业务备份迁移。

`PATCH` 接收 `diagnosis_id`、`module_key`、`suggestion_index` 和 `value`，记录建议被采纳时实际保存的文本和时间。服务端校验建议归属和简历已保存内容，未保存或已被其他修改覆盖时返回 409；重复采纳记录不重复计数。采纳只更新采纳记录，诊断报告和快照保持不变。历史界面同时展示曾采纳情况与当前文本保留情况；评分差异只比较同岗位相同模块，JD 变化单独提示。

当前草稿与诊断快照不同时，采纳确认展示简历 ID、诊断 ID、完整岗位、报告时间和目标模块／条目，说明整段正文或全部技能替换范围。确认及空草稿提示绑定当前简历会话，离页或切换简历立即移除当前／排队弹窗；接受后同事件离页也不调用旧简历写入。确认期间仅保留本条采纳按钮可聚焦，重复点击由同步锁拦截，取消／Escape 返回该按钮、保留改写草稿。工作遮罩区分读取、AI 生成与保存记录，确认期间不显示工作遮罩。原有写入前目标复核仍生效：确认中目标被修改／删除则拒绝覆盖，其他模块变化不影响本条采纳。先排空自动保存、写入后确认保存、再同步采纳记录的顺序保持不变；离页不取消共享保存队列或回滚已提交数据，已写入但待记录的恢复流程沿用原约定。

## 6. 端点清单

投递准备页使用 `GET /api/applications/[id]/preparation` 返回投递信息、各类资料的前 5 条（含 `total`、`nextCursor`）与待办。`resources` 接口接受 `kind=diagnosis|intro|portrait|interview|series|notebook`，`candidates=true` 查询可关联的历史资料，沿用游标分页；POST/DELETE 的 JSON 为 `{ "kind": "intro", "id": 12 }`，取消关联不删除原资料。两种写入成功响应均为 `{ ok: true, preparation }`；写入和完整准备页快照读取都在同一事务内完成，成功后客户端可直接用该快照更新页面，不必再发起一次 GET，读取失败则写入一并回滚。`tasks` 的 POST 接受 `title`（1–200 字），PATCH 接受 `id`、`done`（布尔值），DELETE 接受 `id`，跨投递修改返回 404。

准备页首读、刷新及关联写入快照统一核对当前投递 ID、必要展示字段、六类资料页、唯一待办 ID 及轮次归属；残缺或串投递回包不替换原资料。资料分页核对完整条目、记录链接、ID 降序及游标推进，坏页保留原内容与游标供显式重试。待办 POST 回包须为合法新 ID、与本次提交一致的规范化标题／截止时间及未完成状态；PATCH／DELETE 与资料关联均须严格 `ok:true`，不能将可解析 JSON 当作完成确认。

关联选择器的候选列表也按资料类型校验完整条目、链接与 ID 游标边界，拒绝标记为已关联的候选；任一坏条目整页拒绝。首页失败只重读候选，续页失败保留已有候选并重读原游标，不触发关联写入；合法历史时间及技术字面量继续保留。关联结果未知时弹窗说明“关闭此窗口并刷新资料核对”，不展示重试关联，其他候选的关联入口禁用；关闭仍可用，准备页刷新核对不自动重发写入。明确拒绝时仍可由用户主动重试原资料或选择其他候选。

资料／待办写入遇到坏确认、网络、408 或 5xx 时不报成功、不清空新增草稿，显示“写入结果尚未确认”并暂停本页准备资料／待办写入、生成及分页。用户可编辑新增草稿，使用“刷新资料”只读核对；读取失败或串投递快照不解除暂停，合法完整快照读取成功后才允许继续，并提示核对刚才的操作。刷新不自动重发 POST／PATCH／DELETE，也不把相同标题推断为本次创建；草稿仍保留，由用户核对后决定下一步。明确的其他 4xx 拒绝可直接修正重试。严格确认已成功、仅后续刷新失败时，仍保留已确认结果并报告刷新失败。暂停仅属于当前准备页实例，不跨页持久化，不回滚服务端可能已提交的操作；一次读取不能保证在途请求以后不会提交。

诊断、自我介绍、JD 考点画像、模拟面试的生成接口支持可选 `application_id`。服务端校验投递存在且简历/JD 与当前投递一致，生成结果与资料关联在同一事务内保存；生成期间投递变更则拒绝归档。历史资料仅明确关联，不按相同 JD 推断投递。准备资料关联与待办数据纳入首版数据库和加密备份。

### 上场计划（岗位准备清单）

工具箱入口为 `/tools/preparation`，可搜索选择投递岗位，也可从投递准备页带 `applicationId` 直接进入。`GET /api/tools/preparation-plans/[id]` 返回当前岗位、`contextKey`、`generatedAt`、`stale` 与清单 `steps`。首次读取不创建清单；`POST` 提交 `{ contextKey }` 生成或更新，同一岗位上下文重复生成保留手动训练进度。`PATCH` 接受 `{ contextKey, key, done }`，只允许更新可执行的手动训练项。输入错误返回 400，岗位不存在返回 404，其余异常为 500 + requestId；写入及返回快照共用事务。

清单根据已保存资料生成，无需调用模型。资料仅认明确归属本投递且匹配当前 JD、简历发布版的记录；自我介绍须有可读的双版本，考点画像和诊断须可读取。进行中的模拟面试提供继续入口，完成后自动更新进度。缺失资料可逐项调用已有生成接口，传递当前岗位、JD 与发布版本；练习题优先采用该岗位画像中的具体问题。每项分钟范围与剩余总时长均为一次整理或练习的参考估算。

手动训练完成记录保存于 `application_preparation_plans`，按岗位隔离，纳入业务备份并随投递级联删除。岗位、JD 或简历版本变化会使旧清单失效，重新生成后重新记录训练进度。网络或坏确认不显示为完成，先刷新清单核对后再继续；切换岗位或离页后的迟到响应不替换当前计划。

### 真实面试逐题复盘

`/api/applications/[id]/interviews/[interviewId]/review` 只接受属于该投递的真实面试轮次：

- `GET` 返回 `{questions,input_hash,material_error,latest,selected,history}`；`questions` 是当前草稿，材料有效时 `material_error=null`，`input_hash` 覆盖逐题记录、公司、岗位、JD 和固定简历的职业上下文，`latest` 是最新确认快照。`?recap_id=123` 可读取该轮的指定历史快照到 `selected`；提供时必须为规范正十进制安全整数。每份快照的 `exports` 标记已加入的错题、追练套题 ID 与已创建的待办；必填的 `source_context` 返回 `{company,role,round_name,jd}` 四个文本字段，旧记录未保存资料时为 `null`，明确为空的 `jd` 保持空字符串。
- 已有投递时间时只使用当时保存的简历快照；当时未关联简历则保持无简历背景，不使用之后补关联的版本。尚未固定投递快照时使用当前绑定的发布版。职业字段损坏时，`GET` 仍返回 `200` 和已有逐题记录／历史复盘，但 `input_hash=null`、`material_error` 为修复提示，不伪造空材料摘要。保存逐题记录、生成前及保存生成结果前仍严格检查完整性，损坏返回 `422`；摘要必须是 64 位十六进制字符串，空值或非字符串返回 `400`。
- 材料损坏时页面暂停编辑与生成，保留历史选择和三类导出，并提供“修复后重新加载”。重读失败保留已显示记录；成功后同步当前草稿和摘要，恢复可用操作但不自动生成。重读沿用弹窗请求互斥与取消机制，切换轮次后的晚到响应无效。
- 首读、材料重读和写入回包在更新页面状态前核对完整结构、材料状态、历史顺序、复盘归属及摘要。保存另核对返回题目与本次提交按服务端规则去除首尾空白后的内容一致；生成另核对最新结果的摘要及原题属于本次确认。异常成功回包不报已保存、不覆盖本地编辑或旧结果，保留显式重试；历史选择仅接收归属和原历史摘要一致的所选版本，不推进草稿保存基线。
- 页面回看历史只切换 `selected`，导出只更新对应快照的 `exports`；二者不推进本地逐题草稿的 `input_hash`，避免旧编辑借用后台的新摘要绕过冲突检查。历史读取以最后选择为准，保存或生成会取消在途历史读取；切换投递/轮次或离开弹窗会取消所属请求，过期响应不改写新页面或触发导出后跳转。
- 复盘结果展示该版本生成时的完整公司／岗位／轮次，非空 JD 可展开逐字查看；明确为空时显示“生成时未提供 JD”，缺来源快照时显示“生成时岗位资料未保存”。来源字段缺失、结构或类型错误的回包不替换页面。导出确认同时说明当前归属与生成时资料；追练明确告知使用原 JD 或不附岗位背景，错题说明来源名称，修改待办仍属于当前投递。
- 放弃编辑及三类导出确认均绑定当前投递／轮次的取消信号；离页立即移除当前或排队确认，同步锁防止重复确认及与编辑、保存、生成、切换历史并发。确认展示投递 ID、完整公司／岗位、轮次 ID／名称；导出另展示复盘 ID、原始创建时间及处理数量。取消／Escape 保留草稿并归还触发按钮焦点。
- 导出回包须匹配复盘 ID、投递、轮次、原快照摘要及用户已查看的 `source_context`（四个文本字段逐字相同，或同为 `null`），包含合法导出标记且本次操作确已完成；追练另要求 `drill_id` 为正安全整数并与快照标记一致。异常回包不更新标记、不报成功或跳转，保留原草稿供显式重试。服务端可能已提交，离页取消本地等待不会回滚导出；本页不自动重复 POST，也不提供跨页持久回执。
- 复盘生成请求取消时返回 `499`，不归档晚到结果、不修改已有快照或导出关联，并释放命令锁。未取消的模型错误仍返回 `502`，可按原记录重试。
- `PUT` 接收 `{expected_hash,questions}`，每题包含必填的 `question` 和可留空的 `answer`、`stuck`、`feedback`。最多 20 题，每字段最多 2000 字，总计最多 32000 字。空数组可清空草稿；版本冲突返回 409。
- `POST` 接收 `{expected_hash}`。至少保存一题后，一次 AI 调用生成 `mistakes`、`drills`、`resume_suggestions`，各条用 `question_index` 指向确认时的原题。结果和原题以不可变快照保存；同一完整输入重复确认直接返回已有结果，相关投递上下文变化后可生成新结果并保留历史。保存或确认使用过期摘要、或生成期间逐题记录或投递上下文变化均返回 409，不保存过期结果。模型只读取简历的职业字段（已投递时读取当时快照，尚未投递时读取绑定发布版本），排除全部基本身份、联系方式、文档标题和排版字段，不修改存储快照。AI 结构无效返回 502。
- `POST .../review/export` 接收 `{recap_id,action}`，`action` 为 `mistakes|drills|resume_suggestions`。用户确认后分别批量加入错题本、创建可直接开始的追练套题、创建本投递的简历修改待办；同一复盘版本重复请求不会重复创建。导出依赖已存复盘和所属轮次，不因当前简历材料损坏失败；回包中的 `input_hash`／`material_error` 与 GET 一致。追练响应另含 `drill_id`。跨投递或跨轮次返回 404。
- 新复盘在保存结果的同一事务中记录生成时的公司、岗位、轮次名称及 JD。导出追练使用该版本的 JD（包括明确为空的 JD），错题来源和追练标签使用当时名称；后来修改投递或轮次、删除导出目标后重新导出均不改变这份来源。旧复盘没有保存这些资料时仍可导出，JD 留空并标注“生成时岗位资料未保存”，不从当前投递回填。已导出的独立记录不自动重写。

逐题草稿与确认快照通过 `application_interviews` 关联原投递；删除轮次会级联删除它们。已确认导出的错题、练习与待办作为独立记录保留。

### 模拟面试首题的材料提交边界

`POST /api/interviews` 在请求开始时固定指定或当时最新的发布版，并在保存单轮或系列首轮的同一事务中复核版本归属与实际传给模型的职业材料。参考简历、所选版本删除、归属变化或职业材料变化时，通过 SSE error 明确提示核对材料后重新生成，不发送首题 delta / done，不新增场次、首题、系列或投递资料关联。投递 JD、绑定发布版或存在性变化保留具体业务提示；未知异常仍由统一错误收口处理。

后来编辑草稿、发布新版本、修改其他版本、标题、排版及未传给模型的身份字段，不影响已固定且职业材料相同的请求；省略版本时也不会在保存前偷换成后来发布的版本。页面沿用失败时保留配置、重新读取历史及显式重新开始的流程，不自动创建或认领记录。

### 模拟面试逐题作答的提交依据

`POST /api/interviews/[id]/answer` 在保存评分的同一事务中复核实际评分依据：场次的 JD、风格、题数、简历及版本绑定、系列与轮次、状态，当前题的身份、题号和原题，本轮已答历史的身份、顺序、题型、原题及原答，以及实际简历职业材料、提供给模型的前轮反馈与原题。历史 ID 仅用于提交核对，不传给模型。等待模型期间不持有事务；资料变化、当前题已答或已有下一题时，SSE error 提示“面试资料、当前题目或上下文已变化，请重新读取面试状态后再提交”，不发送评分 delta / done。此时响应已经开始，不能将其解释为 HTTP 409。

拒绝旧结果不保存评分、补全收藏、创建下一题或结束场次；这些写入继续在同一事务中完成。页面沿用不缓存的 GET 核对、保留回答草稿和显式重试流程，不自动重新作答。已固定发布版不因当前草稿、后来发布、其他版本或不传模型的标题、排版、身份字段变化而误拒绝；旧点评、评分、参考和未提供的前轮原答也不参与比较。旧未绑定场次继续读取草稿，实际职业材料变化会拒绝旧评分；原先已缺失的材料仍沿用既有占位，不自动改用其他材料。成功时仅按既有规则补全空收藏字段，完整独立收藏、复习排期与作答历史保留。

### 模拟面试参考、重答与报告的职业材料复核

逐题 `reference`、`retry`，以及场次 `finish`、`evaluator-report` 的 POST 在模型调用前固定实际职业材料，并在原保存事务内复核。所选发布内容、归属或旧未绑定场次的草稿职业内容变化，或原可读发布材料变为损坏结构时，返回 `409`，不更新原题参考、追加重答、补全收藏或归档报告。题目已被级联删除时，参考和重答沿用 `404`；场次和题目的既有冲突检查继续保留。总结与独立评估错误提示明确包含背景材料变化。

固定发布版不会因后来编辑草稿、新发布版、其他版本、标题、排版或未提供给模型的身份字段变化而误拒绝。起始已经缺失的材料继续使用既有占位，不偷换其他版本或当前草稿；初始损坏材料仍由原错误收口处理，提交复核不将未知数据库故障当作材料冲突。已保存重答的同编号、同原答请求直接回读原结果，即使材料后来损坏也不重新评分；被材料冲突拒绝且未保存的请求可在核对后沿用原编号显式重试。页面保留原参考、候选人报告及重答草稿，不自动发起新的生成请求。

### 模拟面试 ID 边界

`POST /api/interviews` 的 `resume_id` 与 `POST /api/interviews/[id]/answer` 的 `turn_id` 必须为 JSON 数字类型的正安全整数；布尔、数组、对象、数字字符串、空值、非整数、非正数及超出安全整数范围的值返回 `400`，不调用模型、不改动存档。单轮与进阶创建遵循同一来源校验，正常数字 ID 的行为保留，数字字符串不再兼容；题数及发布版的既有校验不变。

面试详情 GET / DELETE、作答、结束报告、主考官报告、反问、逐题参考与重答，以及进阶面试详情 GET / DELETE、推进与总评的所有路径 ID 均要求正安全整数，无效返回 `400`。合法但不存在的场次、系列返回 `404`；参考与重答的题目不存在或不属于该场面试也返回 `404`。作答沿用原业务约定：有效轮次 ID 对应已答或不存在的题目（包括另一场题目）返回 `400`，已结束场次也返回 `400`。拒绝请求不改变原题原答、独立收藏、复习排期及作答历史。

### 模拟面试原答评分与报告汇总

详情 GET 按原值读取四维完整、有限的 0–10 数字评分，保留历史小数，不取整或回写。未答题的空评分列或旧 `null` 仍显示为无评分；已答题缺分，或任意题的非空评分 JSON／结构损坏时，该题返回 `scores:null` 和非空 `scores_error`，原题原答及其他合法评分仍可查看。此显示占位不表示原存储已清空；客户端拒绝同时携带有效评分和错误标记的矛盾回复。原答视图显示核对提示，独立重答历史继续按自身状态读取，重答不会修复或覆盖原评分。

`POST /api/interviews/[id]/finish` 要求每道已作答题都有有效原评分，缺失或损坏时在模型调用前返回 `422` 和具体题号，不生成部分平均分或零分报告。未答题不参与汇总；合法小数直接参与各维平均，仅最终均值保留一位小数，综合分仍按既有五维规则计算。模型等待期间评分变化由现有事务快照检查返回 `409`，不提交过期报告。核对或恢复有效原记录后，用户可明确再次生成；已有完整报告继续沿用原读取规则，本轮不重写其存储值。独立录用评估仍只使用原始问答，不依赖旧分数。

### 模拟面试报告与反问保存回执

`POST /api/interviews/[id]/finish` 成功返回 `{interview_id,report,evaluator_report,finished_at}`，`evaluator_report` 无可用结果时为 `null`；`POST /api/interviews/[id]/reverse` 成功返回 `{interview_id,ok:true,reverse}`。`interview_id` 是本次实际保存的面试 ID，报告／反问内容和时间均来自本次保存结果，原有字段保留。

页面只在回执归属、完整结构与必要时间字段通过校验后标记保存已确认；挖掘报告还须含完整挖掘成果，反问须与实际发送的问题逐字一致。坏回执按保存状态未确认处理，仍由不缓存的详情 GET 核对，不直接用 POST 内容覆盖页面，也不自动重发。读取失败保留原页面、草稿与只读恢复入口；合法详情证明当前结果存在时正常恢复，尚无结果时沿用显式重试流程。此回执不提供持久幂等编号，也不保证一次空快照可以排除尚在处理的写入。

### 模拟面试重答

`POST /api/interviews/[id]/turns/[tid]/retry` 接受 `{answer}`，可携带 UUID 格式的 `Idempotency-Key` 请求头（大小写归一）。成功返回 `{retry,retries,reference}`，其中 `retry` 为本次提交对应的版本，`retries` 为提交时的完整历史；`reference` 是原题参考，重答参考仅属于 `retry.reference`。

- 相同题目、相同编号和回答再次提交时直接返回已保存结果，不追加历史或再次评分；应用重启后仍可恢复。相同编号用于不同回答返回 409，非法编号返回 400。未传编号时保持每次独立重答的兼容行为，不按相同文本去重。
- 同一应用进程中，相同题目与数据世代的相同编号仍在评分时返回 409，稍后可用原编号重试；失败和完成后释放在途状态。提交事务再次检查该编号，避免并行提交重复写入，但不承诺多进程部署下所有模型调用都去重。
- 响应中断时调用方应保留编号；修改提交内容或已确认成功后的主动新作答使用新编号。原题、简历、JD、追问上下文及数据世代发生冲突时沿用现有保护，不能用旧页面覆写已恢复数据。
- 详情 GET 和重答回复中的历史为显示投影：旧记录缺失的 answer、comment、created_at 补空字符串，缺失 scores 补 null；已有空日期、无分数、小数分、长正文与缺参考保持兼容，不裁剪或转换错误类型。读取不回写；追加使用原存储记录，保留已有字段和扩展字段。
- 非数组、不可解析、字段类型损坏或重复编号的历史不可追加：调用模型前和提交事务内均校验，返回 422 并保留原记录。详情 GET 仍返回原题原答，并将该题 retries 置为安全显示用的空数组、附上 retries_error 提示；这不表示原历史为空，页面暂停重答，需刷新核对或恢复有效备份。客户端只在回执编号、实际提交正文和对应历史记录一致时确认成功，不用历史末条替代缺失回执。

### 首页今日重点

`GET /api/home/priorities` 接受可选的 `time_zone`（默认服务器本地时区，首页发送浏览器时区），返回 `{date,items}`。`date` 为该时区的 `YYYY-MM-DD` 日期；`items` 最多三项，不足时不补数，每项含 `id,kind,title,reason,badge,urgent,href,action`，`kind` 为 `interview|materials|review`。端点需要登录，所有响应禁止缓存；无效时区返回 400，读取异常返回统一 500，不以空列表掩盖失败。

顺序为：48 小时内面试、逾期复习、7 天内面试、缺失发布版简历或 JD、今日复习、其他准备资料。同一岗位的面试和资料缺口合并，全部到期复习合为一项；同一优先级的岗位按最近面试时刻、投递 ID 排序。已终止投递不推荐，Offer 岗位仅保留真实待面试提醒。资料只认投递明确关联的发布版本、自我介绍、JD 画像和简历诊断。

存在轮次记录时，只从 `scheduled` 轮次中选最近的未来时刻，取消、完成、无效和过期轮次不回退到遗留汇总时间；没有轮次时使用 `next_interview_at`。筛选和后续比较统一解析时间，带时区值按实际时刻处理，历史无时区时间沿用服务器本地时间语义，展示使用请求时区；读取不改写排期。正投递 ID 链接到对应准备页，历史零／负 ID 链接到投递看板，复习项链接到 `/reviews`。

### 间隔复习

- `GET /api/reviews`：`scope=due|all`（默认 due，包含逾期）、`source=all|notebook|remedial`、`time_zone`（IANA 时区，可选，默认服务器本地时区）、`limit`（1–100）、`cursor`。返回 `{items,nextCursor,summary}`；按存储到期日、ID 升序分页，条目的 `sort_date` 明确返回存储排序日期，游标基于该字段。未复习卡的展示 `next_review_date` 为用户当地今日，不能据此推断游标或排序。summary 为全局到期/来源/逾期/今日已复习题数，今日已复习按题去重，来源数量为到期题分区。
- `GET /api/reviews/:id`：返回题目、掌握程度、排期、原作答/参考/点评和历史 `{attempts,nextCursor}`；历史按 ID 倒序，支持 `limit/cursor/time_zone`，界面在主动回忆阶段不展示参考或历史。
- `POST /api/reviews/:id`：`{answer,grade,expected_review_count,request_id,time_zone?}`；answer 为 1–20000 字，grade 为 `again|hard|good|easy`，request_id 为每次提交生成的 UUID。返回 `{card,attempt}`；相同请求重试幂等，复习版本过期或复用编号提交不同内容返回 409。排期与历史在一个事务中保存，不覆盖原作答快照。
- `GET /api/reviews/:id/requests/:requestId`：按复习卡 ID 和原提交 UUID 只读返回 `{request_id,card,attempt}`；`card` 为当前排期，`attempt` 为该编号对应的原答与自评，后续复习或追练转收藏不改变原提交身份。未找到返回 404，非法 ID/UUID 返回 400，所有响应禁止缓存；不创建历史、不推进排期、不按同文回答或最近记录认领。
- 保存从同一事件同步串行并固定原答、自评、版本与编号；正常回包也按编号核对，坏回包、网络、408、5xx 和409先只读恢复。坏读取或串卡/编号/原答保留未知锁；只读404不证明在途写入不会完成，用户只能显式重试同一编号与同一正文，不自动重投或换稿换编号。409 后确实找不到本次提交才重载最新进度，保留草稿和自评；已确认保存后的历史刷新失败独立显示，重读不重复保存。详情和历史续页整份核对同一卡片、完整字段、递减历史 ID 及真实尾游标，拒绝坏页并保留原游标。
- 错题收藏即入列；追练题首次 AI 评分成功后入列；普通练习需要收藏后才加入。未复习卡始终纳入用户当地今日待学习队列，首次复习后才开始固定排期和逾期统计。收藏已在复习的追练题会沿用卡片和历史，删除原练习不影响已收藏题的复习。错题本列表与练习详情提供 `review_card_id`、`review_mastery`、`next_review_date`。
- SM-2 四档自评对应质量分 1/3/4/5：成功间隔为 1 天、6 天、之后乘难度系数，遗忘重置至 1 天；难度系数下限 1.3，间隔上限 365 天。按实际复习日和浏览器时区安排日历日期；掌握程度是复习进度标签，不是科学测得的记忆概率。
- `review_cards/review_attempts` 属于首版数据库结构，随加密备份导出与恢复；复习卡仅在当前收藏或评分流程中创建，不执行启动回填。

复习目录在追加前整页校验条目、来源/到期筛选、当地日期、全局统计关系、严格递增的 `(sort_date,id)` 及末项游标；满页末项才可携带下一页游标。坏页保留已有内容和原游标，显式重试成功才推进，不通过去重掩盖重复边界。全部范围中的卡被另一页面复习后可能向后移动并再次出现，仅在复习次数增长且排序前进时更新原卡并放到新位置。不同日期的页不能拼接，须重载当地新日队列。切换范围/来源即时隔离旧题和统计，刷新重新读取全部已加载页，整批成功才替换；刷新、续页和离页取消相互隔离，客户端读取禁止缓存。

### 简历版本树

简历版本使用 `resume_version_id` 绑定已发布快照。新建投递、模拟面试、自我介绍、简历排雷和简历诊断时校验版本归属；省略版本则绑定当时最新已发布版本，未发布时返回 400。后续回答、重新生成与进阶续轮沿用原绑定。编辑器诊断显式选择已发布版本，投递准备页诊断使用投递绑定版本。

`GET /api/resumes/[id]/versions` 返回 `{ versions, base_version_id, draft_revision }`；列表仅包含版本 ID、所属简历 ID、版本号、父节点、名称、说明和发布时间，不含 `snapshot`。正文和排版快照经 `GET /api/resumes/[id]/versions/[versionId]` 按需读取。`POST` 接受 `{ name, description?, draft_revision }`，发布成功后将草稿来源推进到新版本。`POST .../[versionId]/branch` 接受 `{ draft_revision }`，将历史版本载入草稿；并发修改返回 409，不覆盖新草稿。版本本身没有编辑或删除接口。

数据库结构版本为 `11`，包含当前全部业务表、本机运行表、认证表、索引、触发器与搜索结构。空数据库在事务中初始化为 v11；完整 v1 至 v10 数据库经校验后，在事务中补齐所需的本机创建回执、真实面试复盘来源快照、项目材料表格来源表、简历导入来源运行表、岗位准备清单表、面试题目图谱历史表、MCP 生成阶段与独立补充笔记，失败回滚。旧复盘不回填当前岗位资料，旧材料不按正文标签推断来源。已有 v11 数据库必须通过完整结构与外键校验，其他版本或结构不匹配时拒绝打开。加密备份 manifest 格式版本为 `1.0.0`，加密容器头版本为 `1`，接受数据库版本为 `1` 至 `11` 的完整业务备份；必须包含对应版本的全部业务表、序列、头像清单与结束计数。v1/v2/v3 恢复后复盘来源快照表为空，v4 起必须带该表清单及完整记录。v1/v2/v3/v4 恢复后项目材料表格来源表为空，v5 起必须包含 `project_material_table_provenance` 清单及完整记录；旧版本不能夹带新表。v7 新增 `application_preparation_plans`，v1–v6 备份恢复后该表为空；v8 新增 `interview_question_graphs`，v1–v7 备份恢复后图谱历史为空。v11 新增业务表 `notebook_notes`，旧备份恢复后笔记为空，原题快照保留。来源记录须通过严格 JSON 结构、正文哈希及 UTF-16 标识范围校验，导出、暂存和恢复提交前均检查，失败不覆盖现库；合法来源 JSON 原样往返，无记录表示未知，明确的空标识数组仍保留。认证凭证、会话、创建回执、`resume_import_source_receipts` 及所有 `mcp_*` 运行表不纳入用户备份；恢复提交事务清理导入来源、MCP 草稿与响应缓存并更换世代，失败一并回滚。恢复前的本机原库快照仍可能包含运行数据。用户备份不包含上述运行表，不支持其他格式版本或缺字段的备份。

本机 MCP 在 v9 新增创建回执、操作日志与临时草稿三张运行表，v10 补入生成请求表，均不进入用户业务备份；迁移失败回滚，v9 升级保留已有草稿与回执。生成请求原子认领、跨进程去重，草稿和成功状态同事务提交；重复请求重放缓存，不再调用模型。恢复后保留创建及生成请求防重墓碑，事务内清除临时草稿与生成响应缓存并更换世代，恢复失败一并回滚。详见 [MCP 接入](MCP.md)。

### 项目目录删除与新建

项目目录删除确认固定项目 ID、完整名称、目录中材料数量、最后修改及总结更新时间，并说明全部材料、总结历史、项目练习及作答、直接关联练习题的复习卡片与复习历史会级联删除。独立收藏错题快照及其复习历史、已摘取到简历的内容保留。取消零写入，取消／Escape 后归还触发按钮焦点；离页取消当前或排队确认及所属请求的本地等待。

只有 DELETE 的严格 `{ok:true}` 或 404 才本地移除项目并请求刷新。网络、408、5xx、不可读或不完整成功回包，只执行不缓存的 `GET /api/projects/[id]` 核对；身份、材料页／总数／游标、完整总结及版本元数据有效才确认仍存在。读取失败、坏结构、串 ID 或总结损坏 422 保持未知锁，仅允许“重新读取删除状态”；有效仍存在后须用户再次明确确认才能重删。删除明确拒绝的其他 4xx 保留档案并页内报错。当前页面过滤已确认删除 ID，刷新失败或旧列表不使项目复活，数量按过滤后的目录显示。单次读到仍存在不保证在途删除不会随后完成，没有跨页持久删除回执，离页不撤销服务端事务。

目录整体校验项目 ID、名称、时间和非负材料数，拒绝重复 ID 与残缺条目，不截断历史长名称。新建与删除从同一事件同步互斥，未知删除期间保留并锁定待创建名称。新建读取最新输入并去首尾空白，组合输入 Enter 不创建；正安全整数创建 ID 才允许导航，成功保持锁至离页。创建请求及失败提示属于当前页面，迟到回复不导航新页。未新增项目创建幂等回执，异常后须先核对目录，人工再次提交或重开页面仍可能新增重复项目。

### 项目总结增量更新

总结保存成功返回 `revisionId`、完整 `summary` 和 `summary_updated_at`。页面核对版本递增及正文与本次提交的规范化结果一致后才确认成功。网络、408、5xx 或成功回包残缺／内容不符时，先只读获取同一项目档案；完整新版本包含本次提交内容即可恢复确认，读取失败或结构／身份不符则保留草稿和采纳选择，禁用重复保存并提供“重新读取保存状态”。核对期间的新编辑保留，同一份提案可沿已确认版本继续显式保存；新生成的其他提案不改写其生成依据。合法回读仍不能确认本次提交时保留原编辑版本，后续显式保存继续受事务内版本检查约束，不自动重发 PATCH；当前状态相符只证明档案包含相同内容，不是独立的请求回执。

`POST /api/projects/[id]/summarize` 和仓库扫描的 SSE `done` 返回 `summary`、逐段 `comparison`（`new`/`changed`/`conflict`）、`materialChanges`、`materialFingerprint` 和 `revisionId`。`PATCH /api/projects/[id]` 保存总结时可带 `expectedRevisionId` 与 `proposal: { generated, acceptedKeys, source, materialFingerprint }`；携带的总结版本失配，或草稿对应的项目身份、生成时名称、材料与当前项目不符，均返回 409。逐段采纳会更新 AI 基线；保存文本恰好与本次新稿一致时也记录该文本来源，但未采纳的不同文案仍留在当前档案。首次草稿中直接改写 AI 文案会记录其原稿基线。纯手动保存、或未采用新稿内容的确认，不会把新材料标记为已总结。`GET /api/projects/[id]/summary-history` 按 ID 倒序返回 `{projectId,items,nextCursor}`，支持 `limit/cursor`，`projectId` 精确绑定路径中的项目身份。项目详情材料列表只返回元数据并支持 `limit/cursor`，单份正文通过 `GET /api/projects/[id]/materials/[mid]` 按需获取；材料编辑必须携带 `revision` 对应的 `expectedRevision`，过期返回 409。

`materialFingerprint` 是需原样透传的 64 位摘要，同时绑定项目 ID、生成开始时的名称和材料快照；保存时在事务内复核。同名且材料完全相同的不同项目也不能共用草稿。完整总结、简历三要素和源码扫描均遵循此规则；生成中或生成后改名须重新生成。旧版仅绑定材料的未采纳草稿升级后也须重新生成，已保存档案、历史和材料快照格式不受影响；无关时间戳、其他项目变化及同名写入不会使新指纹失效。

新生成总结区分深度面试分析与简历素材：五维字段每项最多 1,000 字，可分段展开有依据的机制、取舍与 STAR 过程；`techStack`、`brief` 各最多 200 字，`achievements` 最多 10 条、每条最多 300 字，文本总量最多 8,000 字。成果共享项目标题，不逐条重复项目名；明确有来源的项目整体发布状态在 `brief` 统一说明，局部任务的环境、分工与验证状态仍保留在对应成果中，不从版本号或单个未发布版本标题推断整项目状态。源码扫描对超长输出最多请求一次精简，与首次生成共用五分钟截止时间；修正后仍完整校验，不合格时报告具体字段与原因。

页面在接收材料总结或源码扫描草稿时，整份核对完整八字段 `summary`、`comparison`、`materialChanges`、64 位指纹与非负安全整数版本号；差异键与材料 ID 不得重复，差异 `next` 必须与对应的实际采纳正文一致。缺失元数据不再补成空指纹、本页版本或临时差异；坏回包显示生成失败，保留原编辑、已有提案及采纳选择，扫描弹窗保留路径并允许重新扫描，不自动保存。简历三要素返回的旧五维档案沿用存档格式完整读取，不受新生成正文的篇幅限制，也不清理原文的空白、标签和实体字面量。

项目详情按路径项目 ID 创建独立编辑会话：切换时立即移除旧正文、提案、采纳选择、人工编辑记录、材料表单与扫描弹窗，读取失败也不继续展示旧项目操作；返回原项目重新读取已保存档案，不恢复离页前未保存内容。材料总结的正文、完成、错误和收尾回调均核对项目会话与当前请求，旧生成不能覆盖新一轮结果。已发出的保存可能继续在服务端完成，但离开后其回包不刷新旧项目、不改变新项目提示或保存状态；新项目可独立保存。服务端草稿指纹和版本校验继续保留。

`GET /api/projects/[id]` 在同一个同步短事务内捕获项目档案、名称、材料页／总数和总结版本，再在事务外解析与序列化，避免正文与编辑版本失配。同一页面会话的档案缓存不接收比当前版本更低的总结快照：保存确认后晚到的详情或材料续页仍更新材料列表、游标及名称，但保留更高版本的完整总结、更新时间和状态；相同或更高版本正常更新缓存。页面将编辑正文的基准版本独立保存：材料分页、上传／编辑后的详情刷新和保存后的重读不会给仍保留的旧正文换上新版本。仅初始载入、显式放弃草稿切回已读取档案，以及确认本页提交成功时推进对应基准。手动保存携带正文基准；AI／扫描提案的版本若与本地正文基准不一致，保留编辑与提案并提示刷新核对，不发起保存。其他窗口的新档案须重新读取并核对后再继续保存。

材料新增、编辑和删除将写入结果与后续列表刷新分开反馈：写入已确认而读取失败时显示「材料已导入／保存／删除，列表刷新失败」，「重试刷新材料」仅重读详情，不重复 POST／PATCH／DELETE。已提交的粘贴输入与文件选择会清空，等待期间的新输入继续保留；编辑成功先更新本地材料正文与版本，删除成功先移除本地条目。导入与刷新重试各有同步锁，避免同一时刻重复发起；旧刷新及离页回包不覆盖当前刷新状态。明确的输入拒绝继续保留表单并报告原错误。

材料导入 POST 的成功回复须包含正安全整数 `id`，且 `title`、`source`、`filename` 与本次实际提交一致，才清理对应输入；自动标题沿用服务端的正文前 20 个码元规则。网络、408、5xx、不可读或不完整的成功回复保留原稿／文件选择，锁定粘贴与文件两种导入入口，并自动执行一次不缓存的 `GET /api/projects/[id]?limit=50`。核对项目身份、元数据、总数和游标后展示最近一页供人工检查；读取失败或坏结构须先“重新读取材料导入状态”。同名材料和空列表均不能确认本次写入归属，读取成功也不自动清稿或解除锁定。用户核对后明确确认重复风险，才能“核对后解除导入锁定”；此操作保留当前输入，不重发 POST。等待期间的新输入与新文件继续保留，同事件内变更后提交使用最新输入，离页取消所属请求／核对等待及解锁确认。该保护限于当前页面会话，没有服务端幂等回执；解除锁定后再次提交、刷新或重开页面仍可能重复新增，离页也不撤销服务端可能完成的写入。

材料编辑仅在 PATCH 返回 `{ok:true, revision}` 且修订号为 64 位小写十六进制串时确认。网络、408、5xx 或坏成功响应先以不缓存 GET 核对同一材料，身份、完整详情及修订号均有效且标题／正文与提交逐字一致才恢复确认；哈希版本允许正文不变时保持相同。核对失败保留原稿并禁用再次保存，提供“重新读取材料保存状态”，不自动重发 PATCH。显式核对期间可继续编辑，同一编辑会话确认后保留新增修改并推进修订号；切换或取消后重开的编辑器不继承旧操作的版本。有效但不同的存档仅更新缓存，原稿仍绑定原修订号，提示核对后再决定；404 提示材料已不存在并保留原稿供复制。只读核对表明当前存档包含相同内容，不是独立请求回执；离页取消本地等待，不撤销服务端可能已完成的写入。

材料删除从确认开始同步互斥，并与材料编辑保存及未确认的保存结果互斥。只有 DELETE 的 `{ok:true}` 或 404 才确认不存在；坏响应、网络、408 或 5xx 先以不缓存 GET 核对同一材料。核对失败、串 ID 或详情不完整时保留材料，仅允许“重新读取材料删除状态”；有效详情确认仍存在后，须用户重新确认才再次删除，不自动重发 DELETE。确认删除后清理该材料当前编辑器和预览，在本次页面会话中过滤旧列表重新带回的同 ID，包含该条目的旧页总数同步扣除；其他材料编辑继续保留。离页中止所属确认框、删除及核对的本地等待，迟到结果不影响新项目。单次读到仍存在不保证在途删除不会随后完成，不提供跨页持久回执。

材料粘贴 POST 与编辑 PATCH 的 JSON 请求必须为对象，提供的 `title`、`content` 必须为字符串；错误类型（含显式 null）返回 400，不丢弃标题后自动命名，也不部分保存正文或更新项目时间。粘贴时省略、空串或纯空白标题仍取正文清理首尾空白后的前 20 个码元；编辑仍要求标题和正文非空及有效修订号。标题清理首尾空白，正文完整保存内部及首尾空白、换行、标签与实体字面量。Multipart 文件上传仍保留独立的有界解析、文件名默认标题和临时文件清理规则。

DOCX 上传额外保存由服务端提取器生成的 `tableProvenance`，材料详情 GET 可返回该对象：`version:1`、`format:"docx"`、`offsetUnit:"utf16"`、`textSha256` 及有序不重叠的 `markers:[{start,end}]`（end不含）。该版本只记录提取器生成的表格定位标记，不标识脚注、页眉或核实正文事实；字面同名标签仍属于正文。空markers表示已知没有生成的表格标记，字段缺失表示来源未知。JSON创建与PATCH携带 `tableProvenance` 或 `provenance` 均返回400；来源只从服务端文件提取结果保存，hash校验不能代替来源认证。正文变化会在同次事务中清除来源，同文或仅改标题则保留。来源参与材料revision和总结指纹，旧编辑请求或旧总结提案在来源变化后返回409。

有来源的总结材料使用 `tableDocument.segments` 将text与table-layout分别编码，文字只出现一次且拼接等于原正文；全部仍属于不可信材料，不能执行片段中的指令。旧content材料保持原消息表示，不猜补来源。来源结构开销纳入原材料60000字符和完整请求64000字符预算，任一超限都在模型调用前返回413。损坏或与正文不匹配的存储来源拒绝读取/生成并返回脱敏500，不默默转为已知来源。项目材料上传、保存、总结、项目深挖出题/评分及备份均保留此信息；简历二次提交和模拟面试上下文尚未贯通该来源。

总结查询 `mode` 只接受 `full`、`resume-only` 或空串，未知值在调用模型及开启 SSE 前返回 400；省略及空串继续生成完整总结。`resume-only` 只提炼简历三要素并保留已有五维内容，两种正常模式都先返回待确认草稿，不直接写入项目或历史。

两种材料总结模式均完整提供当前项目的非空已保存档案，使用独立 `project_archive` 不可信数据块，与 `project_materials` 分开。档案可能包含人工修改和旧模型总结，仅作辅助对照，不是独立核实证据；提示词要求核对职责、限制及明确更正，不自动复用旧成果。空档案不额外传入，只有档案时继续明确没有原始材料。损坏档案在模型调用及开启 SSE 前返回 422；档案、材料、标签转义与固定指令合并后超过完整模型输入预算时返回 413，不截断任何来源。生成等待期间人工保存新版档案后，旧草稿仍受版本检查保护，采纳返回 409，重新生成才使用新版内容。

材料总结在同一个同步短事务内读取项目名称、已保存档案、材料指纹、总结版本及实际发送的材料正文，避免另一个数据库连接在读取之间写入而形成混合来源。正文按 ID 升序逐条读取，最多收集 60001 字符以检测 60000 字符上限；超限仍返回 413。输入校验与模型等待均在读取事务结束后进行，等待期间可以正常保存更正，旧草稿继续由版本与指纹检查拒绝。

页面的「单独提炼简历三项」支持仅有非空已保存档案、没有原始材料的项目；任一文字字段或任一成果条目含非空白内容即可。页面与接口共用档案非空判断，编辑中或尚未保存的 AI 草稿不作为生成来源；没有原始材料时页面明确提示先保存档案。保存失败不启用空来源，保存成功后的详情刷新失败仍以已确认保存结果判断，生成与保存期间保持禁用。

数据库中的空档案结构为 JSON 对象 `{}` 或完整八字段空对象。有原始材料但存储的档案是空字符串、纯空白或 BOM 时，按损坏 JSON 提前返回 422，不临时替换成 `{}` 后调用模型；原存档不自动修写。无原始材料且档案只有空白时继续返回 400 的暂无内容提示。

总结历史在展示/追加前整页核对项目身份、来源、完整八字段存档、AI 基线、严格递减的历史 ID 和满页末项游标；坏项、串项目、重复边界或错误尾游标整页拒绝。首页失败可独立重读历史，续页失败保留已有全文和原游标，不影响编辑台中未保存的草稿，不重新生成或保存总结。历史空字段、空成果、长文本和时间字面量原样保留，无法解析的时间显示原文；切换项目或总结版本会作废旧分页，迟到响应不能混入新项目。

服务端生成和保存前校验最新历史的 AI 基线与材料快照，复用备份域的完整结构规则。损坏时材料总结、源码扫描在模型／CLI 启动及 SSE 前返回 `422`，手动保存或采纳也返回 `422`，不抹除 AI 来源、不继承坏快照或连带修改项目名称。生成结束时再次校验，等待期间发生损坏只返回错误，不外发可采纳正文；修复历史数据或恢复有效备份后可显式重试。历史 GET 只解析本页实际返回的正文和 AI 基线，损坏时返回 `422`；用于判断下一页的额外行及未展示的材料快照不阻断当前页阅读。当前项目详情与独立重命名不依赖这些历史元数据，继续可用；空基线对象、null／空列表材料快照保持兼容，原始历史不自动修写。

材料总结的完整格式化输入（含材料标题和分隔符）最多 60000 字符。超过时在模型调用前返回 `413`，提示精简材料后重试；不会截取部分材料生成总结，不新增历史或推进材料已总结基线，原材料保留。

`PATCH /api/projects/[id]` 的 `summary` 若提供，必须包含全部当前字段：正文各字段为字符串，`achievements` 为字符串数组；缺失字段、错误类型、未知字段、`null` 和数组根结构返回 400，不修改项目或新增总结历史。合法空字符串与空数组允许主动清空，总结采用整体替换语义。仅修改项目名称时可省略 `summary`。

`POST /api/projects/[id]/evidence-sources` 接受 `{repoPaths: string[]}`，原始数组须含 1–32 个非空目录，沿用仓库扫描的路径校验与受限源码读取，返回 `{sourceFiles}`，不调用模型或保存项目档案。每个文件含 `locator`、`content`、`truncated`、`capturedAt` 与 `receipt`；回执绑定当前数据世代、项目与全部文件字段，有效期一小时，服务重启后失效。创建练习时原样提交所选文件，不以客户端路径重新读盘。

`POST /api/projects/[id]/evidence-drill` 与 `/evidence-drill/recommend` 必须且只能选择一种依据：材料用 `materialId`、`revision`、`startLine`、`endLine`；代码用完整 `scanFile`、`startLine`、`endLine`；已保存档案用 `summaryKey`、完整 `summaryContent` 和连续原文 `summaryQuote`。摘录限 1–280 字，材料和代码行号从 1 开始。服务端核对材料修订、代码回执或当前档案正文；失配返回 400，项目不存在返回 404，损坏档案返回 422。题目保存来源、版本、定位和摘录；Word 材料仅保留所选范围的服务端表格来源，有定位说明时按顺序分别保存正文与定位片段，每段使用 JSON 字符串引用，避免提示词转义改变来源归属。普通正文与来源未知分开，未选择的表头和合并关系保持未知。后续评分及收藏复习使用已保存快照。

手动创建另需 `mode`、`baseline`、`change`：方式来自共用追问清单，原条件最多 80 字，变化条件最多 100 字，自定义变化不能为空。返回 `201 {id,count:1}`；同一项目内完全相同的依据与条件复用已有练习。智能推荐另需整数 `count`（1–5），成功返回 `201 {id,count,questions}`；材料不足可少于请求数量，每题附同一依据快照。模型等待不占用数据库事务，保存前重新核对依据；等待期间依据变化或项目删除返回 400，不保存题目。同项目已有推荐在运行时返回 409；模型输入超限返回 413，调用或返回题目校验失败返回 502，不保存部分结果。

目录浏览 `GET /api/projects/[id]/scan-repo?action=browse&path=...` 先验证项目 ID 与存在性；省略或空白路径时使用宿主用户主目录。指定目标不存在返回 `404`，目标为普通文件、系统报告 `ENOTDIR` 或路径含 NUL 返回 `400`，权限不足（`EACCES`／`EPERM`）返回 `403`，其他读取异常使用统一脱敏 `500`。失败不会改为浏览主目录，也不会伪装成空目录成功。成功返回 `currentPath`、`parentPath`、`drives`、`entries` 和 `truncated`；可见子目录按名称选取最多 200 项，再将带代码工程标识的目录排在前面，超过上限时 `truncated: true`。个别子目录的标识探测失败不阻止父目录列表。页面显示读取失败目标并禁用确认，显式重试同一目标；列表截断时提示可取消后输入完整路径重新浏览。浏览与重试不启动扫描或写入项目材料。

目录浏览的目标检查、列表读取及工程标识探测均异步执行；每次请求最多同时探测 4 个子目录，逐批读取文件名并在发现标识时停止，关闭已打开的目录句柄。请求取消后返回 `499 {"error":"请求已取消"}`，不再调度后续探测，盘符枚举子进程也收到取消信号。已经提交的文件系统操作不能被强制中断，需等待其返回后检查取消并清理句柄；此机制不为慢磁盘或网络文件系统承诺固定完成期限。

仓库扫描和关联预检的 `repoPaths` 原始数组最多 32 项（包括重复项），超过限制返回 400；等价路径在读盘前去重，之后仍按真实路径去重。`POST /api/projects/[id]/scan-repo?action=check-relation` 返回 `isRelated: true | false | null`、`reason` 与 `method: single | model | cli | heuristic`。`null` 表示无法确认关联，`heuristic` 表示模型/CLI 未能给出有效结果后使用启发式判断；界面需在未知或不相关时取得用户明确确认后继续。预检请求失败也必须明确确认，取消覆盖预检、确认等待和扫描全流程。

扫描与关联预检支持 `preferredCli: auto | codex | claude | custom`（默认 `auto`）。`custom` 必须提供 `customCli: {command: string, args?: string[]}`；其他模式不得夹带该字段。`command` 是命令名称或绝对路径（不加外层引号），最长 2048 字符；`args` 默认为空数组，最多 64 项、每项最多 4096 字符，程序与参数总计最多 16384 字符，不含控制字符。Windows 批处理另拒绝无法安全引用的字符及过长命令。结构错误在任何外部调用前返回 400；程序缺失等启动前配置错误通过扫描 SSE `error` 回传，不记为服务器 500。

`custom` 在扫描与关联预检中均使用同一配置，不调用自动探测的内置 CLI，也不将关联预检发给应用内模型。预检失败保持 `null / heuristic` 确认流程。扫描成功 `cliUsed` 为 `custom`；`GET /scan-repo` 仍仅探测内置 Codex / Claude，Auto 不会自动选用浏览器保存的命令。输入一律走 UTF-8 stdin，固定参数不进行 shell 拆分或提示词替换；输出使用现有文本 JSON 解析与八字段校验。具体接入和保存方式见 [自定义客户端](CUSTOM-CLI.md)。

源码扫描将本项目的非空已保存档案以独立 `project_archive` 转义块传入 CLI stdin，标为辅助对照、非独立核实证据；源码仍是判断实现的依据。档案与旧总结不能证明个人主导或实际上线。档案 JSON 损坏时在扫描及 SSE 前返回 422；档案序列化、标签与转义后独立上限为 40000 字符，超限返回 413，不截断档案、不启动 CLI，既有源码采集额度保留。直接领域扫描同样在探测和启动 CLI 前校验；空档案不附加上下文，目录关联预检不依赖档案。生成等待期间保存新版档案后，旧提案继续受版本检查保护，采纳返回 409，重试使用新版档案。

源码安全过滤及预算裁剪后，若没有保留任何非空白文件正文，扫描以 SSE `error` 事件提示“未采集到可用的源码或文档”，不启动模型 CLI、不创建其临时工作目录，也不写入项目或总结历史；这是可补充材料后重试的输入问题，不记录为服务器 500。仓库标题、文件标题、截断标记及旧档案均不能代替本次源码材料；多仓库中只要仍有可用正文就可继续，保持原有材料不足时不得臆造关系的规则。

扫描路由在请求 JSON 读取与路径校验完成后，用同步短事务一起读取当前项目名称、档案、材料快照和总结版本；不把请求体读取前的旧档案配上之后的新版本号。此时项目已删除返回 404，最新档案损坏或超预算分别返回 422／413；目录关联预检同样在读完请求体后复核项目存在。请求体收取、关联模型与 CLI 等待均不持有此读取事务，开始扫描后的修改仍由草稿版本和指纹在保存时复核。

### 设置与本地代理

`GET /api/settings` 返回代理开关、地址和用户名，`proxy_password` 只返回脱敏占位符；`PUT /api/settings` 接受 `proxy_enabled`、`proxy_url`、`proxy_username` 和 `proxy_password`，提交原占位符表示保留已保存密码。代理地址支持 `http://`、`https://` 和 `socks5://`，启用时会校验主机与端口。

`PUT /api/settings` 中显式提供的 `api_format` 只能为 `openai_chat`、`anthropic_messages`、`openai_responses`，`ocr_mode` 只能为 `auto`、`vision`、`local`、`off`；允许字符串两端空格，未知值、空字符串及非字符串返回 `400`，原设置不变。成功响应从实际规范化后的已保存设置生成，API Key 与代理密码保持脱敏。

所有非测试运行保存非空凭证都需要 `RESUME_LIFE_SETTINGS_KEY`。缺少密钥时设置端点返回 `500`、安全的配置与重启提示以及 `requestId`，不回显凭证值；其他未知异常仍使用统一错误收口。已存凭证无法解密时，明确填写新值或清空可替换失效旧值，脱敏占位符仍表示保留旧值并会报告解密失败。

`GET /api/settings/proxy/detect` 从环境变量、Windows 系统代理和限定的回环常见端口生成候选，候选地址不会包含密码；`POST /api/settings/proxy/test` 只执行代理端点握手，不连接外部目标。已启用代理只用于 AI 请求、模型列表和连接测试，不会修改系统代理或代理页面、备份等其他请求。

`POST /api/settings/test` 使用当前或请求体中尚未保存的模型配置，经 `safeChat` 发送非流式最小请求：固定最多 1024 输出 token、整体 15 秒截止，不自动重试，与普通模型调用共用三个并发名额。模型名缺失或配置无效返回 `400`；名额已满返回 `429` 且不转发；上游非 `2xx` 或网络失败返回 `502`；超时返回 `504`，客户端取消返回 `499`；成功返回 `{ok:true,reply}`。成功、失败和取消的上游调用均按“模型连接测试”记录脱敏用量，不保存探测表单配置、凭证或正文。设置页测试期间锁定按钮，离开页面时取消在途请求。

投递面试轮次 POST/PATCH 的 `reminder_minutes` 若提供，必须是非负安全整数，非法值返回 `400` 且不写入；POST 未提供时默认 15，PATCH 未提供时保持原值。创建轮次时的 `advance_stage` 与轮次、下次面试时间及阶段历史在同一领域事务内提交，任一步失败整体回滚。

面试轮次删除确认绑定当前投递／轮次，离页、切换记录或隐藏弹窗会移除所属当前／排队确认，迟到回复不能关闭新弹窗或触发刷新。确认显示持久记录的投递 ID、完整公司／岗位、轮次 ID／名称、面试与创建／修改时间；说明逐题记录、全部复盘及导出关联级联删除，已导出的错题、复习安排、追练和修改待办保留，投递的下次面试时间重新计算。删除与编辑、保存互斥；确认取消／Escape 保留本地草稿并返回触发焦点。

轮次 DELETE 仅严格 `{ok:true}` 或目标端点 `404` 直接确认完成；坏回复、网络异常、`408` 或 `5xx` 先用不缓存 `GET /api/applications/[id]/interviews` 核对。该端点返回完整非分页数组；须逐行验证合法唯一 ID、所属投递、状态及轮次完整字段，确认目标缺席才完成。列表 `404`、残缺／串投递／重复行及读取失败保持未知锁，保留草稿，只允许“重新读取删除状态”执行 GET；合法列表仍含目标则解除锁并提示核对后重新确认。不自动重发 DELETE，不回滚已送达服务端的删除，也不提供跨页持久回执；一次回读不能保证在途删除以后不会提交。

轮次 POST/PATCH 的请求体也必须为对象，提供的 `round_name`、`interview_time`、`interviewer`、`location`、`meeting_url`、`notes` 必须为字符串；错误类型及显式 null 返回 400，不创建轮次、部分改写排期、同步下次时间或推进阶段。`advance_stage` 省略时为 false，提供时必须是 JSON 布尔值；字符串 `"false"`、数字、null、数组及对象不能触发或代替阶段推进。HTTP 与领域入口共用校验；合法空白可选文字、空串清空、默认状态、零分钟提醒与 true 时的既有阶段推进条件保留。

投递 PATCH 的 `stage` 与轮次 PATCH 的 `status` 省略时保持当前状态；显式提供时必须是各自合法枚举字符串，null、空串、布尔值、数字、数组、对象及未知字符串返回 400，整组拒绝，不保存同次提交的其他材料、排期、投递快照或阶段历史。创建 POST 保留省略/null/空串分别默认 `interested` / `scheduled` 的兼容规则。HTTP 与领域写入共用状态解析，非法领域输入抛 `ApplicationInputError`，不依赖 SQLite CHECK 报错。

### 作品集静态站点导出

`GET /api/portfolio/sources` 返回 `{resumes,projects}`。简历条目包含已发布版本元数据，项目条目包含项目库总结；此接口只读取本机数据，不生成或发布站点。

`POST /api/portfolio/export` 接受 JSON 对象：必填 `resumeId`，可选 `versionId`、`selectedProjects`、`siteTitle`、`siteSubtitle`、`accentColor`、`themeMode`、`siteTemplate` 和 `anonymizeConfig`。`siteTemplate` 可取 `flow`、`focus`、`chronicle` 或 `sidebar`，默认 `flow`。项目选择项使用 `{projectId,customLinks?,featured?,order?}`。未指定版本时使用当前草稿，指定版本时读取该简历的不可变发布快照。领域模块先组装简历与项目，再按脱敏配置处理，最后生成静态 ZIP。

`themeMode` 可取 `auto`、`light` 或 `dark`，默认 `auto`。首次打开时优先使用访问者已保存的合法主题；没有保存值时使用显式指定的 light/dark，auto 跟随系统。页面主题按钮会保存访问者的新选择；存储不可用时仍能使用指定主题并切换。

提供 `accentColor` 时必须为六位十六进制颜色（例如 `#b8722c`，大小写均可），其他格式返回 `400`。当前草稿包含损坏模块时返回 `422`，不生成 ZIP；合法空模块仍可导出，指定有效发布版本时使用其快照。编辑器中的作品集导出会先等待简历保存队列完成，保存失败或版本冲突时保留草稿与弹窗并停止导出。

成功响应为 `application/zip`，包含附件名与 `Content-Length`，不会自动上传或托管站点。非法 JSON、null、数组或无效选择返回 400；找不到简历或版本返回 404；Content-Type 非 JSON 返回 415；正文超过 1 MiB 返回 413。未知异常返回统一 500 与 `requestId`。脱敏配置由用户选择，下载内容仍须人工检查后再公开。

`POST /api/portfolio/preview` 接受与导出相同的 JSON 对象、版本选择和脱敏配置，经相同的领域组装与脱敏后返回 `{html,resumeHtml}`：`html` 为作品集预览，`resumeHtml` 为独立简历 HTML，不生成 ZIP、不上传或发布。此端点需要登录，并沿用上述请求校验与 400/404/413/415/422 错误；两份 HTML 合计受展开内容预算限制，超限返回 413，未知异常返回统一 500 与 `requestId`。

### 面试题目图谱

`POST /api/interviews/question-graph` 接受 `{action,resume_id,resume_version_id,jd,style}`，`action` 为 `start` 或 `expand`。简历与发布版 ID 必须为正安全整数且版本属于该简历；JD 必须非空，风格使用面试配置的固定枚举。接口沿用登录校验、请求体及模型输入预算，并以 SSE 返回结果。

`start` 返回 `{question,branches,graph_id,revision:0}`；每条分支为 `{label,predicted_answer,followup_question}`，必须恰有两条，成功后立即保存为独立图谱历史记录。`expand` 另需 `graph_id`、当前 `revision` 和 `frontier` 数组，每项为 `{question_id,depth:2,question,parent_question,answer_scenario}`，最多两项，ID 不可重复且只能含 1–40 个 ASCII 字母、数字、下划线或连字符。可携带最多七项的 `known_questions`，返回 `{expansions:[{question_id,branches}],graph_id,revision}`，完整覆盖请求中的 ID，并在保存时将旧图加入可撤销快照。版本冲突返回 `409`。

新题不得与本批其他题或提供的已有题重复；大小写、全半角、空白、末尾标点及指定排版字符的变化仍算重复。题目最多 800 字符，回答最多 1000 字符，分支标签最多 80 字符。无效模型结果通过 SSE error 拒绝，前端保留旧图并允许重试。未知异常使用统一脱敏错误及请求 ID。

页面每次扩展一个第二层节点，完整图谱共三层七题。独立页面 `/interviews/question-graphs` 提供按更新时间游标分页的历史列表；`GET /api/interviews/question-graphs/[id]` 返回图谱、最多两个撤销快照和生成条件，`POST /api/interviews/question-graphs/[id]/undo` 接受 `{expected_revision}` 并恢复上一步。图谱历史纳入 v8 业务备份，不新增模拟面试记录或投递准备资料。载入历史后可继续扩展或撤销；若原发布版本已删除，仍可查看，但不能基于其他简历版本继续扩展。

### 进阶面试推进

`POST /api/interviews/series/[id]/advance` 必须携带 JSON `{from_interview_id:number}`，绑定发起页面的上一轮面试 ID，不再接受无请求体的隐式“推进最新轮次”。ID 须为正安全整数，来源须属于该系列且为可继续推进的已结束轮次，并已有单轮报告。

服务端仅创建来源轮次的下一轮；目标已存在时直接返回该面试，即使其他页面已结束目标轮次、创建第三轮或生成总评，也不再次调用模型、不修改记录。创建与已有结果均返回 `201 {id,round_no}`，调用方不应根据状态码推断是否新建。详情与总览都发送各自已读取的上一轮 ID，响应异常时仍使用 GET 核对原目标。

缺失或无效字段、非法 JSON 返回 400，非 JSON Content-Type 返回 415，正文超过 1 MiB 返回 413；来源不属于本系列、末轮无法推进、轮次已变更或保存前材料/来源实体发生变化时返回 409。来源尚未完成或缺少报告返回 400。生成使用既有命令锁及事务核对；此约束避免旧请求越轮，不承诺多个服务进程同时生成时完全消除重复模型调用。

创建新的下一轮时，提交事务同时复核实际使用的简历职业材料；所选版本内容或归属变化返回 409，整组首题不写入并释放命令锁。已绑定系列仍使用固定发布版，不因当前草稿、后来发布、其他版本或身份排版变化误拒绝。旧未绑定版本的系列沿用当前草稿作为依据，模型等待时草稿职业材料变化也返回 409，用户显式重新推进才读取新材料。目标轮次已存在时仍按上文直接返回，不因当前简历材料变化重新生成。

### 错题目录筛选与分页恢复

`GET /api/notebook` 按收藏 ID 降序返回 `{items,nextCursor}`。`category_id` 省略表示全部，规范值 `0` 仅表示未分类，其他值要求规范正十进制安全整数；非法分类筛选返回 `400`「无效的分类筛选」。`source` 省略或空字符串表示全部，只接受 `drill|interview|application_interview`，其他值返回 `400`「无效的来源筛选」，不静默扩大检索范围。分页仍统一通过 `parsePaginationParams` 解析。

关键词 `q` 去除首尾空白后，仅在题目、原始回答和点评中检索，不包含参考答案、来源说明或分类名。沿用 SQLite 默认 LIKE 的字面量语义：百分号、下划线和反斜线不作为通配符，只忽略 ASCII 大小写，保留内部连续空格、换行与 NUL 边界。

目录在追加前整页核对条目结构、分类/来源/关键词及请求游标：ID 必须严格递减且续页全部小于请求游标，非空下一页游标必须等于末项 ID，空页不能带下一页游标。任何坏项、串筛选、重复边界或错误游标均整页拒绝；首页失败提供重读，续页失败保留已显示内容和原游标，显式重试成功才追加。校验保留历史长文本、空字段和时间字面量；四维完整、有限的 0–10 数字评分由 `safeScores` 保留原小数，客户端接受相同范围的小数。旧数字字符串仍沿用原有归一化兼容，损坏评分返回 null；读取不改写收藏快照。有复习卡时完整返回关联 ID、进度及下次复习日，无卡时三项均为 null。

练习详情、错题本、首页综合分和 `GET /api/review` 共用上述历史评分读取规则。合法数字小数直接参与来源、场次、项目及全局统计，各维最终均值保留一位小数，再按四维计算综合分；未答题和无效评分不计入。面试原答继续使用严格数字校验，缺分或数字字符串等损坏数据按其 `scores_error` 协议提示，不借用旧兼容路径生成报告。新模型评分的整数要求及诊断报告的历史归一化不变。

首页的“模考与练习”按现存面试和练习记录计数，包含未作答、进行中及已结束记录，不作为完成场数；简历数量不包含发布版本，同公司多个岗位的投递分别计数。历史四维均分是十分制作答均分，不代表录用概率。没有有效评分时显示“暂无评分”，与 AI 配置状态无关；练习或模考完成一次有效评分即可参与统计，合法零分显示 `0.0`。数据库计数、投递统计与评分各自读取、独立降级：读取失败显示 `—` 和刷新提示，不伪报为零数量或没有评分，其他已成功读取的统计继续展示。`getOverallScore` 只在无有效评分时返回 null，读取异常交由首页捕获，不改写任何记录。

复盘后端按练习／面试各自的题目记录 ID 倒序扫描有效已评分作答，每类最多纳入 10,000 条。`totals` 的场次数只统计这些作答对应的场次，作答数、来源／整体均分、场次趋势、维度分析与项目分布全部使用同一纳入范围；`truncated:true` 不是仅截断趋势图。页面明确提示范围限制及部分场次可能只计入部分题目，其余记录仍保留；统计卡使用“已评分场次”“纳入统计的作答数”“本次统计综合均分”，不把受限汇总称为全周期或累计全部。各项目的题量为纳入范围内已评分的项目练习作答数，不作为项目能力深度。

复盘趋势图按已返回场次每页展示 20 场，默认最近一页，页内保持最近作答时间的升序；可用前后按钮或场次范围选择器访问全部已加载场次，不抽样丢弃历史。横轴为完整场次列表中的序号，按容器实际宽度绘图，窄屏文字不随固定画布缩小。原生展开明细支持键盘和触屏，显示该页完整标题、时间、计入题数、综合分及四维分数；雷达图另提供精确数值表，无来源评分明确显示“暂无评分”，合法零分显示 `0.0`。显示分页不重新请求接口、不改变总览统计，也不突破后端每类最多 10,000 条有效作答的聚合上限。

维度分析只比较本次四维均分，最高／最低并列时完整列出相关维度，最低项统一标为“并列较低”或“相对较低”；四维相同（包括全零或全十分）时明确没有分数高低差异，不依赖固定排序制造强弱或指定核心补强项。分数条提供 0–10 的可访问数值，零分填充为零，不人为保留最小长度。原题、点评及各维评价说明继续用于选择具体练习重点。

复盘客户端显示前校验整份快照：完整统计／来源均分、合法四维与综合分、唯一且来源相符的场次、非递减的时间字面量、场次与作答数量关系、每类预算及项目题量。空数据要求数量与列表为空、全部均分为 null；有作答却缺分、数字字符串、坏记录、重复／逆序场次或互相矛盾的计数整页拒绝，不过滤坏项、补零或显示空记录引导。历史长名称、空文本、旧时间字面量及合法零／负 ID 保留；不能由已舍入场均分反算后端原始作答均分，因此不把这种二次舍入差异视为数据损坏。前后端共用每类 10,000 条的预算常量，查询与计算规则不变。

读取显式禁止缓存，离页取消本地等待，迟到成功／失败不能污染新挂载页面。坏成功回复及网络／服务端失败显示页内错误与“重试加载”；只有用户主动重读才再次 GET，等待时显示加载，合法完整回复才展示统计或空记录引导。此恢复流程不调用模型或发出业务写入；取消本地等待不保证已发送的服务端读取停止执行。

来源与搜索入口在首次加载、空目录、筛选无结果和读取失败时均保留；分类、来源、关键词使用 JSON 元组隔离查询。当前分类未出现在最新分类列表时明确显示仍在应用的分类，可切回全部或重新选择，不擅自切换筛选，也不直接断言分类已删除。长分类及来源说明允许换行，所选分类的背景与徽标圆角适配多行文本。

### 独立补充笔记

`GET /api/notebook/[id]/note` 返回 `{note,revision}`，未填写时 `note:null`；已有笔记包含 `{id,notebook_id,content,created_at,updated_at}`。`PUT` 接受 `{content,expectedRevision}`，使用刚读取的 `revision`，成功返回同一结构；正文为 0–20000 字字符串，空串清空内容，禁止 NUL。路径 ID 和参数无效返回 `400`，收藏不存在返回 `404`，网页或 MCP 更新后的旧版本返回 `409`。读取禁止缓存。笔记独立存储于 v11 的 `notebook_notes`，不覆写题目、原答、点评及参考快照，进入用户备份并随错题删除级联清理。MCP `save_notebook_note` 共用同一事务和版本校验。

### 收藏写入与来源只读核对

`POST /api/notebook` 接受 `{source,source_id,category_id?}`；`source` 为 `drill|interview`，`source_id` 必须是数字类型的正安全整数，非空 `category_id` 也必须是数字类型的正安全整数，不强制转换布尔值、字符串或数组。成功 `201 {id,review}` 必须包含正安全整数收藏 ID 与完整复习卡 ID、进度及下次复习日；源题快照、复习卡转接/创建、面试准备关联继续在同一事务中写入。来源与源题 ID 的数据库唯一约束阻止重复收藏，已有收藏返回 `409`，不覆盖原快照或移动分类。

新增 `GET /api/notebook/lookup?source=drill|interview&source_id=正安全整数`，精确读取该来源身份当前对应的 `{id,source,source_id,category_id,question,answer,comment,reference,review}`；`source_id` 只接受规范正十进制安全整数。来源已删除仍可读取独立快照；历史收藏缺复习卡时 `review:null`，GET 不创建缺卡、不改写原文或重置复习进度。无匹配收藏返回 `404`，无效来源参数返回 `400`，所有响应禁止缓存；不按同文题目、最新条目或其他来源认领收藏。

星标收藏从同一事件开始同步串行，固定来源、原题和分类选择；行内创建、编辑分类、取消与再次收藏在等待或未知状态互斥。正常写入回包也要按来源核对当前收藏，首次核对要求返回 ID 与写入确认一致；坏回包、网络、`408`、`5xx` 或已收藏 `409` 先只读核对，不自动重投。回读必须完整包含同一来源身份、合法分类和复习关联，保留历史长原文与空字段；读取失败、串来源、坏结构或确认 ID 不符时保留未知锁，只能显式重新读取。

回读得到相同分类的当前收藏才更新星标和复习入口；分类不同则保留本次选择，显示现有分类及可展开的完整快照，由用户显式“使用现有收藏”，不自动 PATCH 或覆盖历史。只读 `404` 仅说明当前未找到，不证明在途写入不会稍后完成；保留选择并提示风险，须显式“保留选择并允许重试”解除锁，该按钮本身不发送 POST，随后仍需用户提交。重新读取与采用现有快照、解除锁从同步状态互斥，旧入口不能越过正在进行的新读取或写入。

收藏命令按来源、源题 ID 及当前收藏 ID 划分挂载会话；离页中止本地等待，迟到成功/失败不能通知新旧页面或覆盖新锁。恢复状态只属于当前会话，取消本地等待不保证撤销服务端写入，未新增持久收藏回执或跨页面恢复保证。成功提示仅确认当前来源的收藏状态，不声称已有记录必然由本次请求创建。

### 错题分类命令与只读核对

`GET /api/notebook/categories/[id]` 返回 `{id,name,entry_count}`，题量由当前收藏实际计数；成功及不存在的 `404` 响应禁止缓存。GET、PATCH、DELETE 的路径 ID 均要求正安全整数，无效返回 `400`。分类目录整份校验 ID、名称唯一性和非负题量，保留历史长名称；读取失败有独立重试入口，不用空目录掩盖错误。

新建、改名、删除和移动从同一事件开始同步串行，固定本次名称、分类及对象，等待和未知状态锁定提交、编辑与关闭；删除从确认开始锁定，取消零写入。新建仅接受匹配规范化名称的正安全整数 ID，其他命令仅接受对象 `{ok:true}`。坏成功回包、网络、`408` 或 `5xx` 先只读核对，不自动重复写入；明确的其他 `4xx` 保留原稿并恢复操作入口。

删除分类的全局确认绑定本次命令取消信号，所属弹窗卸载或离页时关闭当前项／移除排队项并结算等待，不影响其他有效确认。确认阶段保留删除触发按钮，取消或 Escape 后归还焦点，同步命令锁继续阻止重复确认与写入；接受确认后的下一步仍核对归属，离页前尚未发送的删除不继续。取消本地等待不撤销已经送达服务端的事务。

新建按完整分类目录中唯一名称的当前存在状态核对，不认定同名项必然由本次请求创建；目录请求本身的 `404` 不能证明目标名称不存在。改名和删除读取同一分类 ID，移动读取同一收藏 ID 的原文及 `category_id`；串对象、坏结构或读取失败保持未知锁，只能显式重新读取。有效回读不符合目标时保留原稿，说明在途请求可能稍后完成，再由用户决定是否重新操作；仅同一对象的详情 `404` 可确认删除完成，改名或移动则提示对象不存在。

行内新建与父级收藏/移动双向同步互斥，中文输入法组合期间 Enter 不触发写入；长分类和完整原题允许换行、滚动查看。分类读取刷新与写入恢复各自显示真实错误，不因列表失败丢弃已确认选择或用户原稿。删除分类只将其中收藏设为未分类，收藏快照、复习卡、复习历史及求职准备关联继续保留；多表写入事务中任一步失败整体回滚。

恢复状态只属于当前挂载会话，离页中止本地等待，旧响应不能刷新新会话或释放其锁；取消本地等待不保证撤销服务端写入，单次回读也不保证在途写入不会随后完成。未新增持久命令回执或跨页面恢复保证。

### 错题移出与只读核对

`GET /api/notebook/[id]` 返回收藏快照的 `{id,category_id,question,answer,comment,reference}`，其中 `category_id` 为正安全整数或 null，供分类移动结果核对；成功及不存在的 `404` 响应禁止缓存。读取不改写原文，来源已经删除时仍可读取独立快照。GET、PATCH、DELETE 的路径 ID 均要求正安全整数，无效返回 `400`。DELETE 沿用事务内删除收藏记录及外键级联的行为，对应复习卡、复习历史与求职准备关联一并清理；来源记录、分类、投递及其他收藏继续保留，删除中途失败整体回滚。

错题目录和练习/面试详情星标共用移出流程。确认显示收藏 ID、完整题目、来源类型及可用的来源说明/分类，并明确快照及复习历史的删除范围；来源记录可能早已删除，这份快照可能是唯一副本。取消零写入，确认按钮为“移出”。从确认开始同步串行，目录分类弹窗与移出互斥，星标收藏写入与移出也互斥；仅严格的 `{ok:true}` 或 `404` 确认不存在后移除本地入口、刷新目录/分类及复习提醒。

坏成功响应、网络、`408` 或 `5xx` 先以不缓存 GET 核对同一 ID；根对象、相同正安全整数 ID 与四个原文字符串必须完整，不套新生成篇幅限制或清洗历史。读取失败、串记录或坏结构保留未知状态，只能显式重新读取，不自动再次 DELETE；有效回读仍存在则保留收藏并恢复确认入口。目录记住当前挂载页面的已移出 ID，旧列表不能复活记录；已加载页全是已移出项时仍可继续读取更早收藏。目录与分类刷新失败各自提供重试，分类响应整份校验，旧请求及迟到结果不能覆盖新读取。

目录恢复状态与已移出 ID 仅属于当前挂载页面；星标命令还按来源、源记录 ID 及收藏 ID 隔离。同题换了收藏 ID，旧确认、旧删除或旧核对结果不能清除新收藏及其复习入口。离页中止本地等待不保证撤销服务端写入，单次 GET 读到存在也不保证在途删除不会随后完成；未新增持久删除回执或跨页面恢复保证。

### 练习创建与评分 ID

`POST /api/drills` 创建项目练习时，`project_id` 必须为 JSON 数字类型的正安全整数；创建面试追练时，`interview_id` 遵循相同规则。布尔、数组、对象、数字字符串、空值、非整数、非正数和超出安全整数范围的值返回 `400`，不调用模型、不创建练习；合法但不存在的来源返回 `404`。正常数字 ID 的行为不变，数字字符串不再兼容。

创建请求必须为对象；`source` 可省略（沿用项目练习）或取 `project/bank/interview`，显式未知值不再回退为项目练习。提供的 `direction`、`jd` 必须是字符串，错误类型不能被静默丢弃。提供的 `count` 必须是有限 JSON 数字；布尔、数字字符串、数组、对象、null 和指数溢出返回 `400`，不调用模型或写入。合法数字沿用原规则：缺省和零取 5，其他值向零取整后限制在 1–20。

`GET /api/drills` 的可选 `project_id` 筛选仅接受规范正十进制安全整数；非法值返回 `400`「无效的项目筛选」，不会静默移除筛选并返回全部练习。省略参数仍表示不按项目筛选。

`POST /api/drills/[id]/questions/[qid]` 的两个路径 ID 均要求正安全整数，无效返回 `400`；合法但不存在或不属于该练习的题目返回 `404`。拒绝请求不改变题目、收藏快照或复习历史。正常评分仍按既有规则补全空收藏字段，保留完整的独立收藏原答及已有复习排期、作答历史。

项目深挖出题与评分共同读取完整项目档案、材料和已验证的DOCX表格来源。有来源的材料以 `tableDocument.segments` 代替该条 `content`，已知没有原生表格的空标记仍与未知来源区分；全部文本只出现一次，仍作为不可信数据。旧材料消息保持原样，正文中的伪JSON、表格标签或指令不启用新格式说明。上下文包含结构开销后至多40000字符，转义和固定指令组装后至多64000字符；任一超限返回413且不调用模型、不写业务记录，不截断正文或丢掉来源。

初次读取损坏或不匹配的来源返回脱敏500、零模型调用。模型等待期间，来源、正文、标题或材料集合改变，以及来源损坏或背景变得超限，均在提交事务中按背景冲突返回409，不再调用模型，也不写入旧出题/评分或更新收藏及复习数据。仅来源JSON空白/键序或未进入模型的时间戳变化不产生伪冲突。恢复备份仍受数据世代保护，即使恢复后的正文和来源相同也拒绝跨世代旧结果。来源结构只能证明提取布局，不证明材料事实真实。

### 练习删除与只读核对

`GET /api/drills/[id]` 和 `DELETE /api/drills/[id]` 的路径 ID 均要求正安全整数，无效返回 `400`。详情及不存在的 `404` 响应禁止缓存；读取不改写原始题目、回答、批改或复习状态。DELETE 沿用事务内先清理该练习的模型日志标题、再删除练习的行为；题目、直接关联的复习卡及历史按外键级联删除，失败时一并回滚。独立收藏到错题本的快照、已转接的复习卡及其复习历史继续保留，其他练习及匿名计量不受影响。

目录删除确认显示练习 ID、完整来源、项目、方向、JD、重点、创建时间及已答/总题数，并说明删除与保留范围；取消零写入。从确认开始同步串行删除，创建等待阻止删除，删除等待或未知结果阻止创建并保留配置草稿，同一事件的重复创建只发送一次。目录数量标注为当前筛选已显示的场数，不冒充已完成场数或全部历史总数。

仅对象 `{ok:true}` 或 `404` 确认不存在。网络、`408`、`5xx` 或坏成功响应先以不缓存 GET 核对同一 ID 及存档结构；失败、坏结构或串记录保留未知状态，只允许显式只读重试，不自动重复 DELETE。有效回读仍存在时保留记录，恢复确认入口；不套用新生成的长度或题型限制清洗历史。确认不存在后记录当前页面的已删 ID，刷新失败或旧列表响应不能复活记录；本页全是已删记录时仍可继续加载更早记录。成功提示仅说明确认结果及已请求刷新，目录真实错误和重试独立显示，不持续声称正在刷新。

恢复状态和已删 ID 仅属于当前挂载页面；离页中止本地等待，旧确认、旧入口及迟到结果不能影响新页面。取消等待不保证撤销服务端已发生的写入，单次 GET 读到存在也不保证在途删除不会随后完成；未新增持久删除回执或跨页面恢复保证。

### 题库批量导入与异常恢复

`POST /api/bank` 接受 `{direction?,kind?,text}`，按行清理首尾空白、忽略空行，并仅在同一批次内按完整题目原文去重；保留内部空格、技术符号和实体字面量。按去重后的有效题量限制每次最多 500 道，整批在同一事务内写入，返回 `{count}`（201）。不同批次再次导入同文题目仍会新增，不提供跨批次去重或请求幂等保证。

导入请求必须为 JSON 对象；提供的 `direction`、`kind`、`text` 必须为字符串，错误类型（含显式 null）返回 400，整批不写入。省略方向仍为空方向，省略、空白或未知字符串题型沿用默认 `tech` 兼容规则；`behavior` 继续按行为题导入，题目缺省或仅空行仍返回 400。

导入页从同一事件开始同步锁定提交、方向、题型、原文和示例填入；完成响应必须是对象，且 `count` 与提交时识别的有效题量一致，才清空该批原文并刷新目录及方向统计。明确的 4xx 拒绝（408 除外）保留原稿并允许修正；坏完成响应、网络、超时或 5xx 保留全部原稿和锁，不自动再次 POST。离页取消本地等待，旧完成、失败或确认不能影响新页面；这不保证撤销服务端已经完成的写入。

异常后先以不缓存 GET 按本批题型与非空方向读取最近一页、最多 50 道题；未指定方向时读取该题型的全部方向，接口不将空方向作为精确筛选条件。完整核对条目字段、正安全整数 ID、顺序、游标和实际筛选，坏响应或读取失败只允许重新读取。有效快照用于人工核对，同文历史不能认领本批写入，空快照也不证明在途请求不会随后完成；存在后续游标时提示继续使用目录筛选。用户核对后须显式确认重复风险，才保留原稿并允许再次提交，确认本身不发送 POST。重读与允许再次导入从同步状态互斥，旧快照不能绕过正在进行的新读取。此恢复状态仅属于当前挂载页面，没有持久批次回执或跨页面恢复。

允许再次导入的确认绑定本批命令取消信号，离页关闭当前确认或移除排队确认并结算等待，其他有效确认不受影响。确认阶段保留允许按钮，取消或 Escape 后归还焦点，原稿和只读快照继续保留、写入仍锁定；同步确认标志阻止重复确认、重读或再次提交。接受确认只解除本页导入锁，不自动重发，也不撤销上次请求。

`GET /api/bank/directions` 仅统计非空方向，不能将其计数之和作为全题库总数；导入成功及显式核对读取成功后独立刷新，坏结构保留错误和重试入口，不因编辑原稿反复读取。筛选查询键按字段编码，含冒号的方向与关键词不会发生拼接碰撞。

### 题库目录与筛选校验

题库目录按默认每页 50 道读取，在应用 HTTP 成功响应前整页核对题目字段、正安全整数 ID、严格递减顺序、实际方向/题型/关键词筛选，以及后续游标与最后一条 ID 一致。续页每个 ID 必须严格小于发起请求的游标；重复 ID、串页、坏字段或错误游标不能靠丢弃条目/去重后伪装成有效结果。首页失败保留错误和重试入口，续页失败保留已有结果及原游标，显式重试只读取原页，不部分追加，也不清空导入草稿。

`GET /api/bank` 的非空 `kind` 筛选在清理首尾空白后只接受 `tech` 或 `behavior`，未知值返回 400，不能静默取消题型筛选后返回全部题目；省略、空串或纯空白仍表示不按题型筛选。该查询规则与 POST 的未知字符串默认兼容规则分别处理。

关键词校验沿用真实 SQLite LIKE 查询口径：ASCII 大小写匹配、非 ASCII 不扩大为忽略大小写，`%`、`_` 和反斜线作为原样字面量；内部空格、标签和实体不归一化。兼容 LIKE 在 NUL 处结束文本与模式的行为；对应客户端协议已与真实接口及 SQLite 查询回归核对。无题型筛选时保留未知历史题型，完整长题目不套用新导入限制；目录按原有空格与换行展示正文。

方向统计刷新后不再包含当前方向时，保留“全部方向”退出入口并明确显示当前筛选方向，不自动切换查询，也不把未返回的方向伪报为零题。方向按钮通过 `aria-pressed` 表达选中状态。

### 题库删除与只读核对

`GET /api/bank/[id]` 返回 `{id,direction,kind,question,created_at}`；不存在返回 `404`。GET 与 DELETE 的路径 ID 均要求正安全整数，无效返回 `400`。读取不改变存档，保留完整题目及内部空格、换行和实体字面量；查询位于 `bank-storage`，客户端共用的 `bank` 协议模块不依赖 SQLite。DELETE 沿用事务内清理该题的模型日志标题再删除题目的行为，失败一并回滚，匿名计量与其他题目不变。

### 谈薪新建与列表删除

`POST /api/tools/salary-negotiations` 在完整开场及评估通过校验后，用同一事务保存演练与第 1 回合，返回 `{id}`（201）。事务内保存前检查取消信号；取消后不能因模型已经返回而继续创建空壳记录或开场回合。

创建请求必须为对象；提供的 `target_company_tier`、`target_role`、`expected_salary`、`current_or_competing_offer`、`hr_style` 必须为字符串，岗位与期望薪资不能为空。`hr_style` 去除两端空白后只取 `pressure/standard/emotional`，省略时取 `standard`；企业类型仍支持自定义字符串，省略时取 `top_tech`，筹码省略时为空字符串。错误类型（含显式 null）或未知风格返回 400，校验在创建回执认领前完成，不消耗编号、不调用模型、不新增演练，也不能把错误筹码当作空值匹配旧回执。修正后可使用尚未被认领的原编号正常创建。

可选请求头 `Idempotency-Key` 接受小写 UUID v4，页面会在提交前生成并暂存此编号。同一编号在模型调用前通过 SQLite 事务认领，同时绑定规范化的公司类型、岗位、薪资、筹码和 HR 风格哈希；相同编号且相同有效输入在完成后返回原 `{id}`（200），包括服务重启后的重放。处理中或不同输入复用编号返回 409，已失败编号返回 422，结果已删除返回 410；这些重放均不调用模型、不新增演练。新编号代表显式新建，不按相同岗位或筹码自动合并。未带编号的旧调用者沿用原创建行为。

`GET /api/tools/salary-negotiations/requests/[requestId]` 返回 `{request_id,status}`，状态为 `pending`、`failed`、`deleted` 或 `succeeded`；完成状态另含正安全整数 `id`。无效编号返回 400，未找到返回 404；404 只代表该次读取，不证明迟到请求不会执行。接口鉴权且禁止缓存，回执不返回输入原文或哈希。处理中回执不自动过期或重新执行，服务意外停止时可显式核对历史后另建新编号，但不会撤销原请求，原请求仍可能完成。

回执保存在本机运行表 `salary_creation_requests`，只记录编号、输入哈希、状态、结果引用及时间；完成状态与演练/开场同事务提交。失败不留下演练空壳；删除演练将结果引用置空并保留防重墓碑。同一数据库文件下跨进程认领，重启后保留；备份导出排除此表，成功恢复清除本机回执并更换数据世代，恢复失败一并回滚。v1 至 v10 数据库在校验完整结构后，以事务补齐所需运行表、复盘来源快照、材料表格来源表、岗位准备清单表、面试题目图谱表与独立补充笔记表并升级到 v11；旧版用户备份仍可恢复，缺少的历史业务资料保持为空。

新建页面先同步锁定提交与表单，在当前标签页的 `sessionStorage` 保存编号、规范化背景及文档数据世代；暂存失败不发送 POST。刷新或返回列表后恢复同一背景，只读核对原编号，不自动重发。每次核对都先以不缓存 GET 读取请求回执，必须匹配原编号与完成状态；即使 POST 已返回有效 ID，也不能跳过回执。初次核对时 POST 的 ID 与回执 ID 不同则保留锁并提示记录不符，不读取或导航至串入的记录；用户显式重读后按原编号重新取回实际结果，不缓存失败核对中的错误 ID。取得回执中的正安全整数 ID 后，继续使用不缓存的详情 GET 核对所属记录、公司类型、岗位、薪资、筹码、HR 风格、完整开场及一致的创建时间，再进入对战室。核对失败保留锁，不能用另一请求或同文历史认领。无法取得 ID 的网络、408、409、5xx 或协议异常仍保留原编号、背景和历史核对入口；超时不代表原请求已撤销。历史读取失败时不能放开新建，恢复后须用户显式确认。恢复操作同步检查当前阶段，旧的重读、历史核对和允许另建回调不能抢跑新 POST、解除后续命令锁或重复完成导航。核对成功或显式允许新建时移除当前请求的暂存，不误清其他请求；关闭标签页清除浏览器暂存，已提交的服务端请求不会被撤销。恢复后的新数据世代不采用旧暂存。切页中止本地等待，迟到结果不能导航或刷新新页。

本地创建暂存的清理须同时匹配原编号、完整五项背景及当前文档数据世代，背景对象的字段顺序不影响匹配，正文及内部空白保持原值。暂存被移除、替换、同编号改稿、损坏或变为另一世代时，完成核对不能导航，明确拒绝和人工另建也不能静默释放锁或清除当前记录；提示刷新页面核对。损坏暂存经用户核对历史后清除时，必须逐字匹配初始化读到的原始记录；初始化无法读取原记录时不能盲删后来出现的数据。存储读取或移除失败继续保留未知状态，不自动提交。

### 谈薪回合与结束操作

`POST /api/tools/salary-negotiations/[id]/turn` 和 `/finalize` 的路径 ID 同样要求正安全整数。两者请求体必须携带最近详情 GET 返回的 `expected_revision`；缺失或格式无效返回 400，版本过期返回 409，均在模型调用与写入前拒绝。不能只用当前回合数补造版本。回合成功返回 201 及完整回合，包含所属 `negotiation_id`、实际 `turn_no`、保存的 `user_message` 和时间；结束成功响应包含 `{id,status:"finished",final_package,finished_at,report}`，`finished_at` 与数据库实际保存值一致。两种成功响应另含 `base_revision` 和 `revision`，分别为同一保存事务中实际写入前、写入后的完整存档版本。两条写路径沿用同记录共享的处理锁与事务内背景快照校验；结束保存前也检查请求取消信号。

客户端提交固定当时已读的版本；只有成功响应的 `base_revision` 与提交版本一致、且新版本有效并已推进时，才把结果合并到本地历史。另一标签页已推进报价时，旧页原话与结束补充不会被直接附到未读报价之后。冲突后完整回读最新存档、保留两份草稿，由用户核对并明确重试，不能自动重复提交。生成等待期内未参与生成的旧点评等变化仍允许保存，但实际基础版本会随之变化，客户端须完整回读，不能把新版本令牌与旧点评混装。

`/finalize` 请求体必须为对象，提供的 `final_words` 和 `agreed_package` 必须为字符串；错误类型（含显式 null）或非对象请求返回 400，不丢弃补充材料后生成报告或结束演练。省略及空白字符串仍允许无补充结束，`agreed_package` 非空时保留候选人补记方案，否则沿用模型报告中的方案摘要；完成请求体校验后，已结束记录仍仅回读存档。

已结束记录再次调用 `/finalize` 也须携带当前版本，旧版本返回 409。当前版本仅回读并核对原报告及实际回合引用，此时响应的 `base_revision` 与 `revision` 相同；保留历史小数、评级、长内容和旧空对象的缺失字段。报告缺失、无效 JSON 或结构异常返回 422，不重新调用模型、不覆盖报告、方案或结束时间。新增结束补充也不触发重新生成；页面只对进行中的演练提交结束操作，已结束状态通过详情回读展示。

客户端将发送、结束及删除确认串行化，核对成功响应的记录身份、回合、原答和字段结构。异常后先以不缓存的 GET 读取同一存档，不自动重复 POST/DELETE；读取失败或串记录时只允许重新读取操作状态。收到非超时的 HTTP/协议响应并完成有效回读后可由用户显式重试；网络断连或 HTTP 408 且未读到新增匹配回合或已结束复盘时继续待确认，旧存档不能证明在途操作已经结束。历史已有的同文原答不能认领本次提交，恢复到新增同文回合也保留草稿并提示无法按请求确认来源。恢复入口同步核对当前阶段，旧渲染保留的重读回调不能在后续发送、结束、删除确认、DELETE 或导航期间插入核对、释放新锁或重复完成导航。删除只在 `{ok:true}` 或 404 确认不存在后导航；切页中止等待并隔离迟到回调。这些状态仅属于当前挂载页面，不提供持久请求幂等，单次 GET 也不保证服务端不会随后完成操作。

## 7. 健康检查

`GET /api/health` 返回：

```json
{
  "status": "ok",
  "uptimeSeconds": 123.4,
  "db": { "status": "connected", "version": 6, "journalMode": "wal", "storageWritable": true },
  "latencyMs": 3,
  "timestamp": "2026-09-22T00:00:00.000Z"
}
```

不只验「能连上」：还要求数据库处于 WAL 模式、且数据目录可写——只读目录、磁盘写满、WAL 退化这三类真实故障都靠这两项暴露。任一不满足返回 `503`。

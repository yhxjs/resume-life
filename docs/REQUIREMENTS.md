# resume-life 需求文档

> 本文是研讨会决议的汇编，作为开发的直接输入。术语以根目录 [CONTEXT.md](../CONTEXT.md) 为准，架构决策见 [架构决策记录](./ADR.md)。

## 1. 产品定位

AI 辅助的求职准备工具，个人自用：唯一用户即求职者本人，通过本机用户名和密码登录，无注册、无多租户（[ADR-0004](./ADR.md#adr-0004)）。围绕求职准备提供以下能力：

> 本节的能力清单以 [src/components/layout/site-nav.tsx](../src/components/layout/site-nav.tsx) 的导航项为唯一事实源，
> 由 `src/lib/__tests__/docs-capability-contract.test.ts` 守住一致性：导航新增入口而文档没跟上时，CI 会红。
> 本文其余章节是 v1 研讨会的完整决议；除下文显式标注「已被取代」的条目外逐条仍有效，只有这份清单随产品迭代增补。

1. **简历管理** — 导入已有简历自动结构化入库，或逐模块手动填写；导出打印式 PDF 与 Markdown
2. **样式工厂** — 自定义模板 CRUD、AI 生成与实时 A4 预览
3. **知识库** — 沉淀项目材料，AI 自动总结，摘要内容可摘取进简历
4. **模拟面试** — 输入岗位要求、选择简历，逐题动态出题的文字面试，结束后出总分与总结报告
5. **题目练习** — 项目深挖题基于项目生成；岗位通用题按 JD/方向出题、题库作参考；作答后多维度打分
6. **自我介绍** — 按简历与 JD 生成 30 秒/2 分钟两版自我介绍，逐句点评打磨，背诵遮罩辅助记忆
7. **复盘看板** — 汇总练习与面试的多维评分，按场次画趋势、按项目聚合
8. **错题本** — 从练习或面试收藏题目，收藏即快照，按自定义分类整理（ADR-0003）
9. **岗位题库** — 手动导入岗位通用的八股与行为题，按方向归类，供题目练习出题时参考
10. **求职看板** — 投递记录与阶段漏斗、面试日程，关联简历与面试
11. **工具箱** — 轻量求职小工具集，当前包含 5 个工具：JD 考点画像、面试黑话与暗号解码器、简历排雷与防御演练、离职原因与空窗期对策库、Offer 谈判与薪酬博弈模拟器
12. **设置** — 应用内配置 LLM 服务

进阶面试（一面 → 二面 → 三面）与单场模拟面试共用「模拟面试」入口，见 §6.4。

## 2. 技术栈与架构

- **Next.js 全栈单体**（React + TypeScript），一个工程、一个进程包揽前后端（ADR-0002）
- **SQLite** 存储，零运维
- LLM 统一走 **HTTP API**，支持三种协议：OpenAI 兼容（`openai_chat`）、Anthropic Messages（`anthropic_messages`）、OpenAI Responses（`openai_responses`），设置页切换；不引入 Python AI 框架
- 文档解析用 JS 库（pdf-parse / mammoth）提取文本，LLM 兜底结构化

## 3. 简历管理

### 3.1 数据结构

- 系统内可同时存在**多份简历**；简历由六个**简历模块**组成：基本信息、教育经历、工作经历、项目经历、技能、自我评价
- 项目经历模块下的条目（**项目经历条目**）可关联知识库中的**项目**，也可独立手写
- ~~不做版本管理——需要多版本时复制一份简历再改~~（**已被取代**：简历版本树已随 db v11 实现，见 [API.md](API.md)「简历版本树」与 CONTEXT.md「简历版本」词条）

### 3.2 导入（草稿确认制）

支持 PDF、Word（docx）文件上传与纯文本粘贴，共用同一条链路：

```
上传/粘贴 → JS 库提取文本 → LLM 结构化为简历模块草稿 → 用户预览、修正 → 确认后入库
```

- 解析结果永远以**解析草稿**形式呈现，用户确认前不写正式数据
- 解析失败或字段缺失时降级：保留提取的原文，由用户手动归位到模块

### 3.3 手动输入

编辑页为**所见即所得工作台**：左侧实时渲染一页 A4 真实简历（随输入即时刷新，可切换模板），右侧逐模块表单编辑，逐模块保存。

### 3.4 导出

- 简历以 **A4 纸型**预览与导出，追求单页呈现（紧凑排版，内容超出时打印自动分页）
- **多套内置模板**直接套用：经典单栏 / 现代简约 / 双栏专业，预览页一键切换；模板选择按简历保存
- 通过浏览器打印（print CSS，`@page A4`）生成 PDF；同时支持导出 Markdown 源

## 4. 知识库（项目材料库）

知识库只装项目材料，是**项目**的集合；不挂项目的自由散料不在范围内。

### 4.1 项目

- 一个**项目**对应一个真实的（工作或个人）项目，是简历内容的素材源头
- 面试题与模拟面试的项目深挖均从项目取材；同一项目可服务多份简历

### 4.2 材料导入

- 文本类材料：粘贴文本，或上传 md / txt / pdf / docx 文件
- 解析链路与简历导入复用同一套（库提取文本，不依赖视觉模型）
- 材料入库后可随时编辑标题与内容（修正提取错漏），也可删除

### 4.3 AI 总结

- 基于全部材料生成结构化总结条目：项目概述、架构设计、技术亮点、我的职责、难点与成果
- 总结以**草稿**形式呈现，经人工确认采用后才写入项目档案；确认前不影响现有档案与下游功能（§10 草稿确认制）
- 支持补充材料后手动重新总结
- 总结条目属于草稿性质的内容资产，可编辑

### 4.4 摘取到简历

在简历的项目经历条目上发起「从项目摘取」：关联项目 → 勾选总结条目 → 生成简历描述**草稿** → 确认后写入条目（草稿确认制贯穿始终）。

## 5. 题目练习 (Drill)

静态题组练习，与模拟面试的本质区别：题目在练习开始前一次性给定。三种出题来源，开始练习时选择：

### 5.1 项目深挖

基于**单个项目**的静态题组练习。

- **出题**：依据项目档案（材料 + 总结）生成题目，默认 5 题、可调整；只出项目深挖题（背景、架构、难点、权衡、结果），不生成脱离项目的八股

### 5.2 岗位通用（八股/行为）

基于**岗位通用题库**的静态题组练习。

- **题库**：用户手动导入（粘贴文本，每行一题），每道题标注**方向**（如前端、Java 后端，可留空表示通用）与**题型**（**八股** / **行为**）
- **出题**：提供岗位**方向**（可从题库已有方向中选择）或粘贴 **JD**（至少一项），AI 结合方向/JD 出八股与行为题（按岗位侧重搭配、由浅入深排序），**题库条目仅作参考题源**：其中合适的题直接采用，也可补充题库外的新题；题库为空时同样可出题；默认 5 题、可调整

### 5.3 作答与评分（两种来源一致）

- **作答**：逐题文本作答
- **评分**：每题答完即时出分，四个维度各 0-10 分：
  1. **技术深度** — 项目题看是否讲清原理与取舍；八股题看原理与要点，行为题看事例细节与反思
  2. **结构表达** — STAR 完整性与条理
  3. **真实性** — 项目题与项目档案/简历一致，能识别编造；题库题看回答是否具体可信、无套话空话
  4. **完整度** — 是否覆盖问题要点
- 每题另附综合评语与**参考答案**（项目题为改进版示范作答；八股题为标准答案要点，行为题为 STAR 示范作答）

### 5.4 面试追练（报告 → 练习闭环）

从**模拟面试总结报告**发起的题目练习第三来源。

- **发起**：报告页查看短板/低分维度后，手动点击生成一组追练题（默认 5 题）；追练重点为报告中低于 7 分的维度，各维都不低时取最低两维
- **出题**：AI 结合总结报告（维度分、短板、建议）与本场全部问答的逐题失分点出题，变换角度重考失分点、不与原题重复
- **闭环**：完成追练后可回看面试报告对比短板变化，或再开一场模拟面试检验练习效果，形成「练 → 测 → 补 → 再练」循环；面试记录删除后追练题保留

## 6. 模拟面试 (Mock Interview)

基于**岗位要求（JD）**与所选简历的动态文字对话，题目不事先给定。

### 6.1 流程

```
输入岗位要求 → 选择简历 → 面试官逐题出题（文字）
  → 根据回答决定追问或进入下一题
  → 达到预设轮数，或用户主动提前结束
  → 产出总分与总结报告
```

### 6.2 出题规则

- 题源为**混合**：项目深挖题（结合所选简历与关联的项目档案）+ 岗位通用题
- 逐题生成，上一题的回答影响下一题走向（追问或换题）

### 6.3 结束与总评

- 默认 8 轮左右，可调整；任何时刻可提前结束
- **总分**：四维（同题目练习）+ **岗位匹配度**（回答与 JD 的贴合程度），五维加权
- **总结报告**：强项、短板、改进建议；报告的短板/低分维度可手动生成一组**追练题**（见 §5.4），形成「练 → 测 → 补 → 再练」闭环

### 6.4 进阶面试（一面 → 二面 → 三面）

同一岗位的**进阶面试**：串联三轮完整的模拟面试，每轮独立出题、作答与报告。

- **轮次固定**：一面技术面（技术深挖）→ 二面主管面（方案权衡与取舍）→ 三面 HR 面（动机与行为）；面试官风格按轮次固定，每轮轮数统一设置、可调整（开始时设定）
- **串联**：进入下一轮时，前几轮的总结报告（总分、强项、短板）作为下一位面试官的出题上下文——针对暴露的短板换角度验证、避免重复原题；轮内评分点评同样参考前轮反馈
- **推进**：上一轮出报告后手动进入下一轮；每轮仍可提前结束并出报告
- **总评**：三轮报告齐备后手动生成跨轮总评——三轮五维分数合并对比 + 综合得分（三轮总分平均）+ 综合结论、跨轮强项/短板、综合建议
- 进阶面试在面试记录中是一条记录；每轮保留独立报告与追练题入口

## 7. 自我介绍工坊 (Intro Workshop)

按**岗位要求（JD）**与所选简历生成可直接背诵的自我介绍，一次生成两版：

- **两版时长**：30 秒版（约 100-160 字，开场定位 + 最强匹配亮点 + 动机收尾）与 2 分钟版（约 450-600 字，在 30 秒版骨架上展开项目证据与技能匹配）；可对单版重新生成
- **逐句点评**：生成时逐句附 AI 点评——这句话的作用、亮点或风险与改进方向；句子可编辑，修改后该句点评清空，可对整版重新点评
- **背诵遮罩**：背诵模式模糊遮住全部句子（保留字形轮廓辅助回忆），点击逐句揭示或全部显示/遮住
- 只基于简历真实信息生成，不编造经历与数字；生成结果存于工坊内，不写入简历

## 8. 工具箱 (Tools)

轻量求职小工具的集中入口，与主流程解耦；当前包含：

### 8.1 JD 考点画像

粘贴一段**岗位要求（JD）**，AI 解析生成**考点雷达**，用于面试前定向准备：

- **必考技能**：5-8 项考点按必考程度（1-10）排序，雷达图呈现，附判断依据
- **可能追问方向**：3-5 个最可能被深挖的话题，各附 2-4 个可演练的追问问题
- **公司风格猜测**：从 JD 措辞与侧重推断的团队风格及依据（仅为推测，供心态准备）
- 只依据 JD 本身推断，不要求简历；生成结果保存为记录，可随时回看与删除

### 8.2 面试黑话与暗号解码器

粘贴一段 JD 或面试套话，AI 穿透包装滤镜，输出**潜台词解读**：

- 逐条给出原话、真实含义、风险等级与应对建议
- 附反向提问避坑指南与整体踩坑指数
- 内置常见高频暗号速查，可一键填入输入框
- 生成结果保存为记录，可随时回看与删除

### 8.3 简历排雷与防御演练

AI 扮演毒舌面试官，对选定简历**逐行排雷**：

- 圈出假大空、数据疑点、术语堆砌等高危软肋，附面试官会如何追问
- 每条软肋给出防御预案（如何回应、如何补强）
- 抽屉式即问即评自辩对练：面试官发问、候选人作答、当场点评打分

### 8.4 离职原因与空窗期高情商对策库

针对裁员、内耗、裸辞、Gap、考公考研或创业试错等**敏感经历**：

- 重塑为合理求职动机与成长契机，生成 HR 听着舒适合规的话术
- 按场景与人物风格输出多版话术（简版/详版/转向版）
- 可把话术一键送入排雷演练继续打磨

### 8.5 Offer 谈判与薪酬博弈模拟器

输入目标公司等级、期望薪资与竞品底牌，进行**多轮谈判模拟**：

- AI 扮演 HR 施压拉扯，右侧实时拆解说服逻辑并示范高情商话术
- 每轮给出候选人的应对评分与改进方向
- 结束后输出整体谈判总结与最终定调建议

## 9. AI 接入与设置

- 应用内**设置页**图形化配置：base URL、API key、模型名
- API Key 与代理密码使用 `RESUME_LIFE_SETTINGS_KEY` 做 AES-256-GCM 加密存入本地 SQLite；所有非测试运行（含本机开发）保存凭证前必须配置并独立保管该随机加密密钥，重启时沿用同一个值
- **任务级模型分工**：解析、总结、出题、评分可分别指定不同模型（便宜模型做解析与评分，强模型做出题与总结）
- 任何 OpenAI 兼容服务均可接入（DeepSeek、智谱、OpenAI、中转站等）；Anthropic 官方 API 选 `anthropic_messages`，OpenAI 新版 Responses API 选 `openai_responses`

### 9.1 本地数据安全与资源边界

- 开发和生产默认只监听本机回环地址；本产品不提供账号体系或远程同步能力。
- 系统备份使用 `.rlbackup` 加密容器，导出必须设置 12–256 个 Unicode code point 的密码；导入时使用相同密码自动解密并校验，不支持 JSON 文件。
- 备份包含服务地址与模型名等普通 AI 设置，API Key 和代理密码的明文与设备密文均不携带；备份密码不写入数据库、日志、URL 或浏览器存储，也不能找回。
- **恢复默认保留本机 AI 配置**（不覆盖当前设备的 Base URL / API Key / 模型名），需还原备份中的普通设置时显式关闭该选项并重新填写凭证。
- 普通 JSON 请求、文件上传、项目材料正文和模型输入均受共享资源上限约束；列表接口采用稳定游标分页，避免一次性读取全部记录。

## 10. 全局设计约定

- **草稿确认制**：凡 AI 产出正式数据（简历入库、简历摘取写入、材料总结采纳）前，必须经人工确认环节
- 评分量表统一为每维 0-10 分

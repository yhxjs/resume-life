## MCP 1.3 草稿边界复审修复（2026-11-25）

- MCP 允许使用 `__proto__` 等模块键，但网页保存队列曾把它当作对象原型属性，导致保存版本无效并返回 409。模块版本、草稿基础版本及保存状态现在使用无原型字典，草稿恢复和清除后继续编辑也保留正确行为。
- MCP 清空或替换头像后，现在于业务写入和幂等回执提交成功后清理旧文件；清理前复核全部草稿和发布版本的引用。事务回滚时保留原头像，共享引用和幂等重放不会误删文件。
- 新增 14 项回归用例，覆盖特殊模块键的持久化、恢复、缺失修订及网页连续保存，以及头像移除、替换、共享、历史引用和回执写入失败。相关 3 个测试文件共 99 项通过。
- 使用独立 stdio MCP 进程重新执行原始复现：特殊模块键的网页保存返回 200，移除最后一处引用后头像文件已清理。已配置的 MCP 连接完成真实分页读取和预览；所有写入验证使用隔离的合成数据。

类型检查、lint、生产构建及 162 份构建追踪清单通过；相关网页 15 个文件共 92 项通过。真实 Codex MCP 客户端完整工作流、重连、冲突及备份恢复检查，以及 `npm run example:mcp` 均通过。

最终全量 `npm test -- --silent --reporter=dot` 使用 Windows 默认的两个测试进程：625 个文件全部通过，14,391 项通过、1 项既有跳过，耗时 1,193.75 秒。验证期间 58 个改动中的实现与测试文件哈希一致；`git diff --check` 通过。修复后再次检查全部改动及调用链，没有新增可复现问题。改动保留在工作区，未提交。

## ADR-0001：单用户系统与原始账号取舍

> 以下为当时决策；当前认证约束以 [ADR-0004](#adr-0004) 为准，无注册、多租户及 owner 字段的约束继续保留。

状态：历史决策，认证部分已被 [0004 单用户登录与受限 CLI 材料](#adr-0004) 替代。以下记录原始取舍；当前有单用户登录，仍不提供注册、多用户或租户隔离。

resume-life 是求职者的个人工具：唯一用户就是数据的主人本人。我们决定不做注册/登录/多租户，数据模型不设 owner 字段。 曾考虑的替代方案是"自用为主但预留多用户"，被否决——每处查询都要背一层永远用不到的过滤，却换不来任何当下价值。若未来确需多人使用，届时再以显式迁移引入用户实体，而不是现在预埋。

### Consequences

- 所有数据隐式归属于操作者本人，接口与存储层都无需鉴权与隔离逻辑。
- 默认生产启动只监听 `127.0.0.1`，避免无鉴权接口意外暴露到局域网。
- 若需要远程访问，必须靠部署层（VPN 或带身份认证与 TLS 的反向代理）保护，不得直接暴露应用端口；应用层仍不设账号体系。

## ADR-0002：Next.js 全栈单体与 SQLite

单用户本地工具，部署简单性压倒一切：前端（React + TypeScript）与后端 API 同处一个 Next.js 工程，一个进程跑完；数据存 SQLite，零运维。曾考虑的替代方案是 Vue/React + FastAPI 前后端分离——Python 的文档解析与 AI 生态确实更强，但被否决：两套工程、两个进程的运维成本对单人项目不划算；文档解析退化为 JS 库（pdf-parse / mammoth）加 LLM 兜底的组合。未来若解析需求复杂到 JS 生态确实扛不住，再显式引入解析侧车，而不是现在预埋。

### Consequences

- LLM 调用走 OpenAI 兼容 HTTP API，不引入 Python AI 框架。
- 任何"再加一个后端服务"的提议都应先对照本 ADR。

<a id="adr-0003"></a>
## ADR-0003：错题本收藏时保存快照

错题本（`notebook_entries`）不外键关联 `drill_questions` / `interview_turns`，而是收藏时把题目、作答、评分、点评连同来源标签复制进条目，仅以 `(source, source_id)` 记录出处。曾考虑的替代方案是只存来源 ID、展示时实时联查——被否决：练习与面试记录是可删除的一次性产物，联查会让收藏随源记录一起消失，而「回顾过去的薄弱题」恰恰要求收藏比练习记录活得更久。若未来需要收藏态跟随源题更新，再显式提供"重新快照"操作，而不是引入隐式同步。

### Consequences

- 删除练习/面试不会级联清除错题本；错题已有内容是收藏时刻的定格，源题重答后不会自动覆盖。先收藏后生成答案、点评、参考答案或评分时，仅在源题写入事务内补齐收藏中的对应空字段；已有字段与未发生补齐时的更新时间保持不变。
- 列表和详情 GET 只读取已保存快照，不扫描源题、不回填历史条目，也不为补齐申请写锁。
- `(source, source_id)` 上的 UNIQUE 约束保证同一题只收藏一次，同时作为「原题是否已收藏」的判定依据（详情接口 LEFT JOIN 回填 `notebook_id`）。
- 分类（`notebook_categories`）被删除时其下错题变为未分类（`ON DELETE SET NULL`），条目本身保留。

## ADR-0004：单用户登录与受限 CLI 材料

日期：2026-10-01。状态：已采用。

本应用继续使用单用户 SQLite 数据模型，不引入业务 owner 字段、注册或多租户。内置登录保存一组随机 salt 的 scrypt 密码哈希与随机会话令牌哈希，所有业务 API 由统一包装器验证会话；公开入口仅包含认证与健康检查。首次初始化授权在 BEGIN IMMEDIATE 事务内复核，显式重置开关才允许覆写；凭证不属于业务备份。

远程使用仍由反向代理负责 TLS、访问控制与网络隔离。部署者显式设置 `RESUME_LIFE_SECURE_COOKIES=true`，应用不据不可信转发头决定 Cookie 属性。默认回环 HTTP 保持可用，失败登录与密码派生都有固定资源限制。

第三方仓库内容只作为不可信数据。应用读取有预算的源码白名单材料，排除环境文件、凭证、运行数据、依赖、符号链接与仓库代理指令，再用 stdin 交给关闭文件/命令工具的 CLI。CLI 在空临时目录运行，不能依赖仓库配置自行扩大读取范围。资料有可能被预算截断，输出必须基于已有证据，不能把缺少信息当作已全面审阅。

Codex 使用 `--ignore-user-config` 保留认证并跳过用户 model/provider、MCP、插件和 hooks 配置；apps/plugins 与执行功能另显式关闭。空配置表会递归合并，无法删除已配置的 MCP，故不采用该方式。隔离带来的自定义 provider 兼容性变化在 README 说明，用户可改用 Claude 或应用 API。管理员级配置属于部署信任边界。

这部分取代 0001 中“不做登录、接口无需鉴权”的决定，保留其“无注册、多租户及 owner 字段”的约束。

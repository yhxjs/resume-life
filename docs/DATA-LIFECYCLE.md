# 数据生命周期与删除规则

本文是 resume-life 的默认数据治理约定，面向本机单用户或受控服务器部署。应用不提供远程遥测；用户输入、简历、联系方式、上传头像和模型输入只在本机数据库/文件目录或用户配置的 LLM 服务之间流转。

## 数据分类与默认保留

| 数据 | 存储位置 | 默认保留 | 删除/清理方式 |
|------|----------|----------|---------------|
| 简历、投递、面试、题库和工具结果 | `resume-life.db` | 直到用户显式删除或清空数据目录 | 使用页面/API 删除；完全清除时停服后删除整个数据目录 |
| 上传头像 | `data/uploads` | 与数据库引用一致；未引用文件不作为业务数据 | 删除引用后按上传存储清理；完整清除随数据目录删除 |
| LLM 调用计量 | `llm_call_logs` | 最近 180 天 | 每天首次调用前自动清理过期记录 |
| 认证用户与会话 | `auth_users`、`auth_sessions` | 用户重置或会话过期 | 重置凭证清空会话；过期会话按请求懒清理 |
| 恢复前灾备快照 | `data/backups` 及配套 `.uploads` | 最多 5 份，按数据库大小与 256 MiB 最低预算轮转 | 新建快照超预算时清理最旧完整快照 |
| 恢复临时目录 | 系统临时目录 `resume-life-restore-*` | 正常完成立即删除；异常残留超过 24 小时且所属进程已退出才自动清理 | 无法核对所有者的目录保留，需运维确认后手动删除 |
| 用户导出备份 | 用户选择的下载/外部存储 | 不由应用自动删除 | 用户按外部存储策略清理；导出包不含 API Key 和代理密码，包括设备绑定的密文 |
| 脱敏配置及敏感原词 | 当前站点 localStorage 的 `resume_life_anonymize_config` | 保留到主动清除或退出登录 | 设置页“清除本机敏感副本”；退出成功时清除；规则原词可能包含真实公司或秘密项目名称 |
| 项目源码绝对路径 | 当前站点 localStorage 的 `resume_life_project_repo_paths_<数据世代>:<项目ID>` | 保留到主动清除或退出登录；恢复后的新世代不读取旧路径 | 设置页“清除本机敏感副本”及退出时清除全部路径键；路径可能包含系统用户名和保密项目名 |
| 未保存简历标题/正文 | 当前标签页 sessionStorage 的 `resume-life:draft:*`，以及页面保存队列内存 | 用于异常恢复，保存成功后清除；关闭标签页通常结束会话存储 | 设置页主动清除；退出时明确选择清除或保留；浏览器恢复会话可能保留 sessionStorage |

## 删除边界

单条删除会按领域外键和级联规则清理关联记录，但不会自动删除用户自行复制到外部位置的备份。需要完整清除时，先停止应用，保留必要的法律/运维副本后删除整个数据目录及外部备份，并确认 `resume-life.db-wal`、`resume-life.db-shm`、`uploads`、`backups` 和系统临时恢复目录均已处理。

完整清除还必须覆盖浏览器副本：先在设置页执行“清除本机敏感副本”，对每个打开的标签页分别清理后关闭，再清除该站点的浏览器存储/下载文件。清除操作只删除应用拥有的敏感键，不删除其他应用存储；sessionStorage 按标签页隔离，不能声称一次操作已清除其他标签页或其他浏览器 profile。若选择退出时保留草稿，该标签页重新登录仍可恢复，因此共享电脑应选择清除。退出会撤销服务端会话，但撤销 cookie 本身不等于删除浏览器数据。

“保留草稿并退出”仅保留草稿，不保留脱敏规则或源码路径。恢复成功后刷新页面，新文档会采用新的数据世代，旧页面不会通过更新 meta 自动采用新世代。

删除简历时，同一事务会清空该简历及其模拟面试、面试系列和自我介绍的 LLM 调用标题快照，匿名用量计量继续按 180 天规则保留。

单独删除面试、自我介绍、面试系列、项目、练习、模板、题库条目、简历排雷或薪酬谈判时，同样在删除事务内先擦除对应计量标题；删除系列/项目时包含即将级联删除的面试/练习。先删除子实体再删除简历也不会留下这些标题快照。启动及恢复时还会擦除已无对应实体的历史标题残留，匿名计量继续保留。

简历删除事务会在级联删除前收集当前模块和历史版本的本机头像指针，提交成功后逐文件复核全库引用，再删除已无人引用的头像；其他简历当前模块或历史版本仍共享的头像保留。删除事务失败不清理文件，空库孤儿清扫仍保留防止误指向数据目录的保护。

恢复失败留下的快照和无法确认所有者的临时目录属于灾备安全边界，不能由后台静默删除；运维应先确认没有运行中的恢复进程，再按排障文档核对数据库完整性和配套头像目录后清理。

## 凭证与模型外发

模型 Base URL 不接受内嵌账号密码，保存和连接探测返回校验错误，凭证应通过独立字段配置。旧地址中的内嵌凭证会在数据库打开或恢复时移除，设置回显与用户备份也独立移除该部分；日志只记录发生清理，不记录地址或凭证。依赖 URL 账号密码的网关需要重新配置独立认证。已下载的旧备份、SQLite WAL 空闲页及恢复前快照不会被本次清理追溯擦除，仍按上述保留和完整清除规则管理。

AI API Key 和代理密码使用 `RESUME_LIFE_SETTINGS_KEY` 做 AES-256-GCM 加密存储，所有非测试运行（包括本机开发）保存凭证前必须配置该密钥。用户导出的备份会清空凭证的明文与设备绑定密文，保留服务地址和模型名等普通设置；恢复默认保留当前设备配置。关闭保留选项后需重新填写凭证。加密密钥需独立保管；本机可使用受保护的项目根目录 `.env.local`，服务部署可由密钥管理器注入，不能与数据库、上传目录或备份放在同一位置。用户选择远程 LLM 服务时，发送范围由对应功能的 safe-llm 输入边界决定，应用不把模型输出写入服务端日志。

## 运维核对

备份流绑定请求取消信号，具有 60 秒无进展和 30 分钟总时长预算。任务在 reader、暂存或导出读事务清理完成后释放共享名额；恢复还会在事务提交前核对截止时间，失效时沿既有数据库/头像补偿路径回滚。已提交成功的恢复不会因为随后客户端断开而回滚。公开作品集仅按默认规则遮盖基础字段和标题中的同名信息，项目正文、自定义链接和其余业务敏感内容必须在下载后本地检查，再公开发布。

导出连接或暂存清理失败会移交给进程内的清理重试，保留共享名额并续租；认证/解析失败时尚未返回的暂存资源也沿用该机制。清理成功才归还名额，进程退出后按租期回收；重试只清理资源，不重放恢复写入。

1. 定期检查数据库、上传目录、快照和外部备份的访问权限与保留期限。
2. 删除或轮转 `RESUME_LIFE_SETTINGS_KEY` 前先完成凭证迁移/轮换，否则旧密文无法读取。
3. 执行完整清除后，用文件清单和 SQLite `PRAGMA integrity_check` 验证没有遗留运行时副本。
